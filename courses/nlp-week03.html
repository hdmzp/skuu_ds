3.0

왜 전처리가 필요한가원시 텍스트의 문제 · 파이프라인 개요 · 전처리의 최종 목적

원시 텍스트(raw text)는 그대로 사용할 수 없다
  • 사람이 쓴 문장은 컴퓨터에게 단순한 문자(character)의 나열일 뿐이다
  • 머신러닝 모델은 숫자만 이해하므로 텍스트를 수치로 바꿔야 한다

원시 텍스트가 가지고 있는 문제

문제예시무엇이 문제인가
표기 변형“USA”, “U.S.A.”, “United States”같은 대상을 가리키는데 서로 다른 토큰이 된다
불필요한 정보HTML 태그, URL, 이모지, 반복 문자(“ㅋㅋㅋㅋㅋ”)의미와 무관한 잡음이 어휘를 늘린다
철자 오류“Natureal”, “Processin”사전에 없는 형태라 같은 단어가 쪼개진다
형태 변화“study / studies / studying”의미는 같은데 서로 다른 단어로 취급된다
의미 기여도 차이“the”, “is”, “of”자주 나오지만 의미를 거의 담지 않는다
한 줄 정의 — 전처리는 이 잡음을 줄이고, 같은 의미를 같은 표현으로 모으는 작업이다.

전처리 파이프라인 한눈에 보기

  • 전처리는 하나의 기법이 아니라 여러 단계가 순서대로 연결된 파이프라인이다
  • 각 단계는 앞 단계의 출력을 입력으로 받아 점진적으로 텍스트를 정제한다

전처리의 최종 목적

전처리의 목표는 “텍스트를 모델이 학습할 수 있는 수치 표현으로 바꾸는 것”이다.
3.1

토큰화토큰과 타입 · n-그램 · 어려운 사례 · 서브워드 · 한국어 형태소

토큰화(tokenization)
  • 텍스트를 분석의 기본 단위(토큰)로 나누는 절차
  • 무엇을 토큰으로 볼지는 목적에 따른 설계 결정이며 단어 · 문자 · 서브워드 · 형태소가 모두 토큰이 될 수 있다
  • 예) “I am reading a book.” → ['I', 'am', 'reading', 'a', 'book', '.']
  • 한 번에 하나씩 추출한 토큰을 유니그램(unigram)이라 한다

토큰(token)실제 등장한 개별 단위

텍스트에 실제로 등장한 개별 단위. 중복을 포함해서 센다.

타입(type)서로 다른 토큰의 종류

중복을 제거한 토큰의 종류. 타입의 집합이 곧 어휘 사전(vocabulary)을 구성한다.

토큰화는 왜 필요한가

  • 토큰화는 모든 후속 처리의 전제조건이다 — 품사 태깅 · 불용어 제거 · 어간 추출은 모두 토큰 단위로 동작한다
  • 어휘 사전을 만들어야 각 단어에 고유 인덱스를 부여할 수 있다
  • 토큰이 잘못 나뉘면 이후 모든 단계의 결과가 함께 어긋난다 — 오류 전파

토큰화 단위의 선택

단위장점단점
단어 단위직관적이다어휘가 커지고 OOV(사전에 없는 단어)가 발생한다
문자 단위OOV가 없다시퀀스가 길어지고 의미 단위가 사라진다
서브워드 단위두 방식의 절충안 — 현대 모델의 표준분절 결과가 사람이 보기에 낯설 수 있다
핵심 질문 — “무엇을 하나의 단위로 볼 것인가”가 토큰화 설계의 핵심이다.

n-그램(n-gram)

  • 한 번에 두 개 또는 세 개의 토큰을 묶어 추출할 수도 있다 — 두 개는 바이그램(bigram), 세 개는 트라이그램(trigram)
  • 사용하는 이유 — 단어 하나만으로는 알 수 없는 순서 · 문맥 정보를 담을 수 있다
    · “not good”은 바이그램으로 볼 때 비로소 부정 의미가 드러난다
    · “New York”, “United States”처럼 두 단어가 한 개체를 이루는 경우
  • 활용 — 언어모델, 검색 질의 확장, 감성 분석의 피처, 표절 탐지
n-그램의 한계
  • n이 커질수록 가능한 조합 수가 지수적으로 늘어난다 — 희소성(sparsity)
  • 학습 데이터에 없던 조합은 확률이 0이 되어 스무딩(smoothing)이 필요하다
  • 멀리 떨어진 단어 사이의 의존 관계는 여전히 포착하지 못한다
  • 실무에서는 보통 n = 2 ~ 3을 사용하며, 그 이상은 잘 쓰지 않는다

토큰화가 어려운 사례

공백만으로 자르는 단순한 방식은 많은 경우에 잘못된 결과를 만든다.

NLTK 토크나이저 비교

입력 : "Don't stop! It's 3.14 — visit a-b.com @user #NLP :)"
토크나이저성격결과
word_tokenizeTreebank 기반 · 가장 널리 사용['Do', "n't", 'stop', '!', 'It', "'s", '3.14', '—', 'visit', 'a-b.com', …]
WordPunctTokenizer문자와 기호를 무조건 분리['Don', "'", 't', 'stop', '!', 'It', "'", 's', '3', '.', '14', …]
RegexpTokenizer(r"\w+")정규표현식으로 직접 규칙 지정['Don', 't', 'stop', 'It', 's', '3', '14', 'visit', 'a', 'b', 'com', 'user', 'NLP']
TweetTokenizer해시태그 · 멘션 · 이모티콘 보존[…, 'a-b.com', '@user', '#NLP', ':)']
정답은 하나가 아니다 — 데이터의 성격과 목적에 맞는 토크나이저를 선택해야 한다.

실습 ① 단순 문장의 토큰화

import nltk
nltk.download('punkt_tab')
from nltk import word_tokenize

words = word_tokenize("I am reading NLP Fundamentals")
print(words)
['I', 'am', 'reading', 'NLP', 'Fundamentals']

실습 ② 정규표현식 기반 토큰화

규칙을 직접 정의해 원하는 형태로만 토큰을 추출할 수 있다.
from nltk.tokenize import RegexpTokenizer
text = "Contact: hong@ex.com, 010-1234-5678 (2024-03-15)"

# 영문 단어만 추출
print(RegexpTokenizer(r"[A-Za-z]+").tokenize(text))
['Contact', 'hong', 'ex', 'com']

# 숫자를 포함한 토큰 추출
print(RegexpTokenizer(r"[\d-]+").tokenize(text))
['010-1234-5678', '2024-03-15']
도메인 특화 텍스트(로그, 의료 기록, 법률 문서)에서 특히 유용하다.

실습 ③ 문장 단위 토큰화

문서를 문장 단위로 먼저 나눈 뒤 단어 토큰화를 수행하는 경우가 많다.
from nltk import sent_tokenize, word_tokenize
text = ("NLP is fun. It is used in many fields. "
        "Dr. Kim works at A.I. Lab.")
sentences = sent_tokenize(text)
print(len(sentences))   # 4 ← A.I. 뒤에서 잘림
4
for s in sentences:
    print(word_tokenize(s))
['NLP', 'is', 'fun', '.']
['It', 'is', 'used', 'in', 'many', 'fields', '.']
['Dr.', 'Kim', 'works', 'at', 'A.I', '.']
['Lab', '.']
왜 4문장이 되었나 — “Dr.”는 punkt의 약어 사전에 있어 유지되지만 “A.I.”는 사전에 없어 문장 경계로 잘못 나뉜다.
도메인 약어는 직접 등록해야 한다 : tk = PunktSentenceTokenizer(); tk._params.abbrev_types.add("a.i")

서브워드 토큰화 — OOV 문제

단어 단위 토큰화는 학습 시 보지 못한 단어를 모두 [UNK]로 처리해 정보를 잃는다.

BPE (Byte Pair Encoding)

  • 가장 자주 함께 등장하는 문자 쌍을 반복적으로 하나로 병합하는 알고리즘
  • 원하는 어휘 크기에 도달할 때까지 병합을 반복한다

서브워드 알고리즘 비교

알고리즘병합 기준특징 · 대표 모델
BPE빈도가 가장 높은 인접 쌍을 병합GPT 계열에서 사용
WordPiece병합 후 언어모델 확률(우도)이 가장 크게 증가하는 쌍을 선택단어 중간 조각에 “##” 접두어를 붙임 → BERT 계열
SentencePiece공백까지 하나의 기호(▁)로 취급언어에 독립적이며 사전 토큰화가 필요 없어 한국어 · 일본어 · 중국어에 특히 유리
한국어에서는 SentencePiece(Unigram/BPE)가 사실상 표준으로 사용된다.

한국어 토큰화 — 어절 ≠ 단어

왜 이런 차이가 생기나 — 한국어는 교착어(agglutinative language)
  • 하나의 어간에 조사 · 어미가 계속 결합한다 (학교 / 학교가 / 학교를 / 학교에서 / 학교에서만 …)
  • 띄어쓰기 규칙이 느슨하고 실제 문서에서 자주 어긋난다 (“할수있다” / “할 수 있다”)
  • 같은 형태가 품사에 따라 다른 의미를 가진다 (“배” : 과일 / 신체 / 선박 / 배수)
  • → 따라서 형태소 분석기(KoNLPy, Kiwi, MeCab)를 이용한 토큰화가 필요하다

한국어 토큰화의 중의성

3.2

품사 태깅 (POS Tagging)Penn Treebank 태그셋 · 활용 · 방법론의 발전 · 한국어 품사 태깅

  • POS(Part-of-Speech)는 품사를 의미한다
  • 품사 태깅은 문장 내의 각 토큰에 해당하는 품사를 부여하는 프로세스다
  • 토큰의 품사를 알면 관심 있는 품사만 골라 분석할 수 있다

Penn Treebank 태그셋

영어 품사 태깅에서 가장 널리 쓰이는 표준 태그 체계(총 36개 태그).
계열태그
명사 NNNN 단수명사 / NNS 복수명사 / NNP 고유명사 단수 / NNPS 고유명사 복수
동사 VBVB 동사원형 / VBD 과거형 / VBG 동명사 · 현재분사 / VBN 과거분사 / VBP 현재형(비3인칭) / VBZ 현재형(3인칭 단수)
형용사 JJJJ 형용사 / JJR 비교급 / JJS 최상급
부사 RBRB 부사 / RBR 비교급 부사 / RBS 최상급 부사
기타DT 한정사 / IN 전치사 · 종속접속사 / PRP 인칭대명사 / CC 등위접속사 / CD 기수
태그를 외울 필요는 없으며, 앞 두 글자(NN / VB / JJ / RB)만 알아도 대부분 처리 가능하다. 태그의 뜻은 nltk.help.upenn_tagset('VBZ')로 확인한다.

실습 ⑤ 품사 태깅

import nltk
nltk.download('averaged_perceptron_tagger_eng')
from nltk import word_tokenize

words = word_tokenize("I am reading NLP Fundamentals")
print(nltk.pos_tag(words))
[('I','PRP'), ('am','VBP'), ('reading','VBG'), ('NLP','NNP'), ('Fundamentals','NNS')]
PRP는 인칭대명사, VBP는 현재형 동사, VBG는 동명사 · 현재분사(여기서는 현재분사), NNP는 고유명사, NNS는 복수명사다.

③ 구문 분석 · 개체명 인식의 입력 피처parsing · NER

불용어 제거가 오히려 해로운 경우
  • 감성 분석 : “not”, “no”, “never”를 지우면 의미가 정반대가 된다 — “this is not good” → “good”(긍정으로 오분류)

  • 구문 분석 : 기능어가 사라지면 문장 구조를 복원할 수 없다
  • 사전학습 모델(BERT 등) : 문맥 정보를 스스로 학습하므로 제거하지 않는 것이 일반적이다
실무 권장사항 — 기본 리스트를 그대로 쓰지 말고 도메인에 맞게 추가 · 제외 목록을 관리할 것

  • 다르게 표기되지만 의미적으로 동일한 표현을 하나의 표준 형식으로 바꾸는 과정

  • 주의 : “US(미국)”와 “us(우리)”, “Apple(회사)”과 “apple(과일)”이 구분되지 않는다

기법 ② 정규표현식 정제

실제 웹 텍스트에는 분석에 불필요한 요소가 다수 섞여 있다.
import re

def clean(t):
    t = re.sub(r"<[^>]+>", " ", t)                # HTML 태그
    t = re.sub(r"http\S+|www\.\S+", " ", t)        # URL
    t = re.sub(r"\S+@\S+\.\S+", " ", t)            # 이메일
    t = re.sub(r"[^가-힣ㄱ-ㅎㅏ-ㅣa-zA-Z0-9\s.,!?]", " ", t)  # 특수문자·이모지
    t = re.sub(r"(.)\1{2,}", r"\1\1", t)           # ㅋㅋㅋㅋ → ㅋㅋ
    return re.sub(r"\s+", " ", t).strip()          # 연속 공백
정제 규칙은 반드시 순서를 고려해야 한다 — 특수문자를 먼저 지우면 URL 패턴이 깨진다.
또한 특수문자 패턴은 호환 자모만 보존하므로 NFD 조합형 자모는 삭제된다 → NFC 정규화를 먼저 할 것.

어간 추출 (Stemming)동작 방식 · Porter 알고리즘 · 어간 추출기 비교

어간 추출(stemming)
  • 영어와 같은 언어에서 단어는 문장에 사용될 때 다양한 형태로 변형된다
  • products는 굴절형, production은 파생형이다. 어간 추출은 둘을 구분하지 않고 잘라내므로 모두 product가 된다 — 표제어 추출과의 결정적 차이
  • production → (어간 추출) → product  /  products → (어간 추출) → product
동작 방식
  • 사전을 참조하지 않고 정해진 규칙으로 접미사를 잘라낸다
  • 따라서 매우 빠르지만, 결과가 실제 단어가 아닐 수 있다

Porter 알고리즘의 규칙 예시

Porter Stemmer는 5단계에 걸쳐 접미사를 순차적으로 제거한다.
단계규칙과 예시
1aSSES → SS (caresses → caress), IES → I (ponies → poni), S → (없앰) (cats → cat)
1b(m>0) EED → EE (agreed → agree), (*v*)ING → (없앰) (battling → battl)
2ATIONAL → ATE (relational → relate), IZATION → IZE, ALISM → AL
3ICAL → IC (electrical → electric), FUL · NESS → (없앰) (hopeful → hope, goodness → good)
4AL, ANCE, ENCE, ER, IC, ABLE 등 제거
5남은 E 제거 (rate → rat 방지 조건 포함)
규칙만 적용하므로 “battling → battl”, “was → wa” 같은 비단어가 생길 수 있다. 이 한계를 보완한 것이 다음 절의 표제어 추출이다.

표제어 추출 (Lemmatization)표제어란 · 어간 추출과의 비교 · WordNetLemmatizer

표제어 추출(lemmatization)
  • 어간 추출은 “battling → battl”처럼 의미 없는 결과를 만들 수 있다
  • 이 문제를 극복하기 위해 사전(WordNet)을 참조해 실제 기본형을 찾는 방법이다
  • 단어의 품사 정보를 함께 사용하므로 훨씬 정확한 결과를 얻는다
  • 다만 사전 조회와 추가 검사로 인해 어간 추출보다 처리 속도가 느리다
표제어(lemma)란
  • 사전에 표제 항목으로 올라 있는 형태 — was, is, are → be
  • 언어학적으로 타당한 기본형이므로 사람이 읽어도 자연스럽다

어간 추출 vs 표제어 추출

구분어간 추출 (Stemming)표제어 추출 (Lemmatization)
동작 원리규칙으로 접사를 잘라냄사전(WordNet) · 품사 정보를 이용
속도빠르다느리다
결과사전에 없는 형태가 생길 수 있음 (battl, wa)언어학적으로 타당한 기본형 (battle, be)
품사 정보사용하지 않음함께 사용해야 정확도가 오름

tree = nltk.ne_chunk(nltk.pos_tag(word_tokenize(s)))
print([(" ".join(w for w, t in st), st.label())
       for st in tree if hasattr(st, "label")])
[('Packt', 'PERSON'), ('New York', 'GPE')]

# spaCy를 사용하면 더 정확하고 간결하게 처리할 수 있다
import spacy; nlp = spacy.load("en_core_web_sm")
print([(e.text, e.label_) for e in nlp(s).ents])
[('Packt', 'ORG'), ('New York', 'GPE')]
같은 문장에서 NLTK는 “Packt”를 PERSON으로, spaCy는 ORG로 판정했다 — 도구에 따라 결과가 달라진다.
3.9

단어 중의성 해결 (WSD)문맥에 따른 의미 변화 · Lesk 알고리즘

  • “사귀는 친구를 보면 그 사람을 알 수 있다” — 이와 마찬가지로 단어의 의미도 함께 쓰인 다른 단어에 따라 달라진다
  • 철자가 같은 두 개 이상의 단어가 상황에 따라 서로 다른 의미를 가질 수 있다

실습 ⑬ Lesk 알고리즘

기본 아이디어
  • 사전에 실린 각 의미의 정의문(gloss)과 문맥 단어의 겹침(overlap)을 센다
  • 가장 많이 겹치는 의미를 정답으로 선택한다
import nltk; nltk.download("wordnet"); nltk.download("omw-1.4")
from nltk.wsd import lesk
from nltk import word_tokenize

s1 = word_tokenize("I went to the bank to deposit money")
print(lesk(s1, "bank").definition())
a container (usually with a slot in the top) for keeping money at home

s2 = word_tokenize("water flows beside the sloping bank")
print(lesk(s2, "bank", "n").definition())
sloping land (especially the slope beside a body of water)
문장 1은 금융기관 의미를 놓쳤다 — 단순 Lesk는 정의문 단어 겹침만 세기 때문이다(알고리즘의 한계).
3.10

문장 경계 인식 (SBD)Punkt의 약어 사전 · 미등록 약어 문제 · 한국어

문장 경계 인식(Sentence Boundary Detection)
  • 문서를 문장 단위로 정확히 나누는 작업
  • 요약 · 번역 · 질의응답은 모두 문장 단위 입력을 전제로 하므로 매우 중요하다

실습 ⑭ 문장 경계 인식

NLTK의 PunktSentenceTokenizer는 학습된 약어 사전으로 경계를 판단하므로, 사전에 없는 약어는 오분리된다.
from nltk.tokenize import sent_tokenize
text = ("Dr. Kim joined A.I. Lab in 2020. "
        "The price is $3.14. Visit www.ex.com now!")
sents = sent_tokenize(text)
print(len(sents))
4
for i, s in enumerate(sents, 1): print(i, s)
1 Dr. Kim joined A.I.
2 Lab in 2020.
3 The price is $3.14.
4 Visit www.ex.com now!
$3.14와 www.ex.com은 올바로 유지되지만 미등록 약어 A.I.는 경계로 오인된다.
한국어는 종결어미(-다, -요, -까)를 활용하므로 Kiwi의 split_into_sents()가 유리하다.
3.11

전처리 순서 설계와 통합 파이프라인순서가 결과를 바꾼다 · preprocess() 함수

핵심 원칙
① 표제어 추출은 품사 정보를 필요로 하므로 POS 태깅 뒤에 수행한다
② 소문자 변환을 먼저 하면 개체명 인식(NER) 성능이 크게 떨어진다
③ 불용어를 먼저 지우면 문맥이 사라져 POS 태깅 · 구문 분석이 부정확해진다
④ 정답은 없다 — 과제(task)와 후속 모델에 따라 순서 · 포함 여부를 설계한다

실습 ⑮ 통합 파이프라인

지금까지의 단계를 하나의 함수로 연결한다.
import unicodedata
import nltk
from nltk import word_tokenize
from nltk.corpus import stopwords, wordnet as wn
from nltk.stem import WordNetLemmatizer

def preprocess(text):
    text = unicodedata.normalize("NFC", text)   # ⓪ 유니코드 정규화
    text = clean(text)                          # ① 정제 (clean 함수는 앞에서 정의)
    text = text.lower()                         # ② 정규화
    tokens = word_tokenize(text)                # ③ 토큰화
    tagged = nltk.pos_tag(tokens)               # ④ 품사 태깅
    tagged = [(w, t) for w, t in tagged
              if w not in stop_words and w.isalpha()]   # ⑤ 불용어 제거
    return [lemmatizer.lemmatize(w, wn_pos(t))            # ⑥ 표제어 추출
            for w, t in tagged]

def wn_pos(t):
    return {"J": wn.ADJ, "V": wn.VERB, "R": wn.ADV}.get(t[0], wn.NOUN)

print(preprocess("The children were studying NLP books!"))
['child', 'study', 'nlp', 'book']

3.13

NLP 프로젝트 6단계수집 · 전처리 · 피처 추출 · 모델 개발 · 평가 · 배포

  • 프로젝트는 여러 하위 단계로 나눌 수 있으며 이 단계들은 순차적으로 수행된다
  • 각 단계를 전문화된 리소스로 수행하므로 전체 효율성이 향상되는 경향이 있다
1

데이터 수집 (Data Collection)

요구사항에 따라 데이터를 모으는 단계. 기존 공개 데이터셋 활용 · 온라인 저장소 수집 · 웹 크롤링으로 자체 구축한다. 예) 트윗 감성 분석 프로젝트 → 특정 키워드의 트윗을 수집한다.

2

데이터 전처리 (Data Preprocessing)

수집한 데이터를 정제하는 단계로 이번 장에서 배운 기법들이 모두 사용된다. 지저분한 데이터는 모델의 효과와 정확성을 저하시킨다(Garbage In, Garbage Out). 예) 수집된 트윗에서 URL · 멘션 · 해시태그 · 이모지 · 중복 트윗을 제거한다.

3

피처 추출 (Feature Extraction)

컴퓨터는 이진수만 이해하므로 텍스트를 수치 데이터로 변환해야 한다. 단어 모음(BoW), TF-IDF 같은 행렬로 정제한 문서를 표현하며, 최근에는 Word2Vec, GloVe, 문맥 임베딩(BERT)을 주로 사용한다.

4

모델 개발 (Model Development)

피처 세트가 준비되면 데이터에서 지식을 얻도록 학습할 모델을 개발한다. 통계 기반 · 머신러닝 기반 · 딥러닝 기반 · 강화학습 기반 모델이 있다. 예) 수치형 행렬에서 감성(긍정/부정)을 예측하는 분류 모델을 설계한다.

5

모델 평가 (Model Evaluation)

개발한 모델을 벤치마킹하는 과정으로, 다른 모델과 성능을 비교한다. 평가지표는 정확도 · 정밀도 · 재현율 · F1-점수. 클래스 불균형이 있으면 정확도만으로는 성능을 판단할 수 없다.

6

모델 배포 (Model Deployment)

대부분의 산업에서 NLP 프로젝트의 최종 단계다. 모델이 기존 시스템에 통합되거나, 이를 기반으로 새로운 제품을 만든다. 예) 실시간으로 트윗에서 감성을 추출하도록 API 형태로 서비스에 배포한다. 배포 후에도 데이터 분포 변화(drift)를 모니터링하며 재학습해야 한다.

저작권 · 개인정보 · 이용약관 확인이 데이터 수집보다 반드시 선행되어야 한다.

핵심 정리3주차 Summary — 교안 “요약” 슬라이드 전체

① NLP에 포함된 다양한 전처리 단계를 단계별로 다루었음 — 토큰화 → 품사 태깅 → 불용어 제거 → 정규화(철자 · 어간 · 표제어) (3.0 ~ 3.7)

④ 한국어는 교착어이므로 형태소 분석 기반 접근이 필요함 (3.1 · 3.2 · 3.3)

⑥ NLP 프로젝트가 거쳐야 하는 여섯 단계를 살펴봄 (3.13)
