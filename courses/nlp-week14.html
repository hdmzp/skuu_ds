14.1

딥러닝 기반 질의 응답교안 4~8p

질의 응답이란 — 문서 목록이 아니라 정답 그 자체 (교안 5p)

질의 응답(Question & Answering) = 자연어로 주어진 질문에 대해 시스템이 자연어로 정답을 제시하는 과제. 검색(Information Retrieval)이 ‘관련 문서 목록’을 주는 것과 달리, 질의 응답은 ‘정답 그 자체’를 준다 — “대한민국의 수도는?”에 검색은 링크 10개, 질의 응답은 “서울”.

나누는 기준종류예
정답 형태추출형(Extractive) / 생성형(Abstractive) / 선택형(Multiple-choice)지문에서 ‘서울’을 잘라 옴 / 문장을 새로 써서 답 / 보기 4개 중 고름
지식 범위폐쇄형(Closed-domain) / 개방형(Open-domain)사내 규정 · 의료 등 한 분야 / 무엇이든
근거 제공 방식독해형(Reading Comprehension) / 검색 기반(Retrieval-based)지문이 함께 주어짐 / 먼저 문서를 찾아 온 뒤 답
⚠ 분류 기준 섞기 — ‘폐쇄형’은 지식 범위 기준이지 정답 형태 기준이 아니다(100문제 3번). 정답 형태 = 추출 · 생성 · 선택, 지식 범위 = 폐쇄 · 개방, 근거 = 독해 · 검색 — 세 쌍을 짝으로 외운다.

기존 질의 응답 vs 딥러닝 질의 응답 (교안 6~8p)

기존 (규칙 · 통계 기반)질문 → 질문 분석 → 쿼리 → 문서 검색 → 후보 정답 추출 → 정답 추출 → 정답 — 단계마다 사전 · 규칙 · 형태소 분석기 같은 외부 리소스가 필요
딥러닝 (End-to-End)질문 + 문서 → 단어 임베딩 + 신경망 인코더 → 정답 예측 → 정답 — 전체를 손실 함수 하나로 학습
기존 파이프라인딥러닝 기반
필요한 것형태소 분석 · 구문 분석 등 언어학 지식 기반 외부 리소스초기 단어 임베딩용 레이블 없는 큰 코퍼스 외에는 수작업 리소스 불필요
오류앞 단계 오류가 뒤로 전파 — 오류 누적(error propagation)한 번에 학습하므로 누적이 줄어듦
의미 비교사람이 만든 자질질문과 정답 후보를 같은 벡터 공간에 놓고 유사도를 학습(분산 표현)
한계규칙 구축 비용대량의 학습 데이터 필요, 판단 근거 해석이 어려움(블랙박스)
🔎 오류 누적을 숫자로 — 기존 파이프라인의 다섯 단계가 각각 95% 정확하다고 하자. 앞 단계가 틀리면 뒤에서 회복할 수 없다면 전체 정확도는 0.95^5 \approx 0.774, 약 77%로 떨어진다. 단계가 늘수록 더 나빠진다. 딥러닝 모델은 중간 단계를 따로 두지 않고 정답 손실 하나로 모든 층을 함께 고치니, 이런 곱셈식 손실이 생기지 않는다. 대신 사전학습 언어모델을 재사용해 적은 데이터로도 높은 성능을 낸다(교안 6p, 14.3).
14.2

질의 응답 딥러닝 모델 — 샴 · 어텐션 · Compare-Aggregate교안 9~13p

세 모델의 공통 아이디어 (교안 9p) — 질문 문장과 정답 후보 문장을 각각 인코딩한 뒤 두 표현 사이의 연관성 점수를 계산하고, 점수가 가장 높은 후보를 고르는 랭킹(ranking) 문제로 정식화한다. 차이는 ‘두 문장을 얼마나 일찍 · 촘촘히 비교하느냐’다.

샴 네트워크 — 쌍둥이 인코더 (교안 10p)

  • 문장 의미 유사도, paraphrase 식별처럼 문장을 쌍으로 쓰는 과제에 쓰인다
  • 두 입력은 가중치를 공유하는 동일한 구조의 인코더를 통과해 벡터가 된다 — 같은 잣대로 재야 비교가 공정하다
  • 두 벡터로 코사인 유사도 · element-wise 연산 · 신경망 기반 가중합 중 하나로 연관성 점수를 낸다
🔎 왜 가중치를 공유하나 — 질문 인코더와 답 인코더가 따로면, 같은 문장 “서울이 수도다”도 양쪽에서 다른 벡터가 되어 코사인이 1이 아닐 수 있다. 공유하면 같은 문장은 늘 같은 벡터, 비슷한 문장은 비슷한 벡터가 되어 ‘거리 = 의미 차이’가 성립한다. 파라미터 수도 절반이다. 단점은 두 문장을 끝까지 따로 읽다가 마지막에야 비교한다는 것 — 질문의 어느 단어가 답의 어느 단어와 맞는지는 보지 못한다. 그래서 다음 두 모델이 나왔다.

어텐션 기반 모델 — 질문이 답의 단어를 고른다 (교안 11p)

  • 질문과 정답 후보 간 상호작용을 개선하려고 제안
  • bi-LSTM + pooling layer로 질문 표현을 만든다
  • 그 질문 표현을 기준으로 어텐션을 적용해, 정답 후보 문장의 단어 중 질문과 관련 있는 단어에 더 큰 가중치를 준다 → 가중합 표현 → 유사도 점수

예: 질문 “수도는 어디인가”, 후보 “대한민국의 수도는 인구가 많은 서울이다” — 어텐션이 ‘수도’ · ‘서울’에 무게를 싣고 ‘인구가 많은’은 덜 본다. 샴처럼 문장 전체를 한 벡터로 뭉뚱그리지 않는다.

Compare-Aggregate — BiMPM의 5개 층 (교안 12 · 13p)

층 (아래 → 위)하는 일
① Word Representation단어를 일정 차원 벡터로 — 단어 임베딩 + 문자 임베딩
② Context Representation위치 · 문맥 정보를 더해 새 벡터로 — Bi-LSTM
③ Matching질문과 정답 후보의 각 시점 표현을 여러 관점(perspective)에서 비교 — 다관점 매칭
④ Aggregation비교 결과를 고정 길이 벡터로 집계
⑤ Prediction집계 벡터로 최종 연관성 점수 또는 라벨 예측
⚠ 순서 · 이름 — BiMPM(Bilateral Multi-Perspective Matching)은 5개 층, 순서는 Word → Context → Matching → Aggregation → Prediction(‘비교한 뒤 모은다’ = Compare-Aggregate라는 이름 그대로). ‘다관점 비교’는 Matching, ‘고정 길이로 모으기’는 Aggregation(100문제 20 · 21번).
🔎 세 모델을 한 줄씩
모델언제 비교하나비유
샴각자 다 읽고 마지막에 한 번두 사람이 각자 요약문을 써서 요약끼리 비교
어텐션 기반질문 요약을 들고 답의 단어를 훑으며질문 메모를 들고 답안지에 형광펜 칠하기
Compare-Aggregate단어(시점)마다 여러 관점으로 비교한 뒤 모음두 문서를 줄마다 대조표로 맞춰 본 뒤 결론
14.3

사전학습 언어모델 기반 질의 응답과 평가 지표교안 14~16p

BERT로 푸는 추출형 질의 응답 (교안 14p)

  • 대규모 코퍼스로 사전학습한 언어모델을 질의 응답 데이터로 미세조정한다(13주차 BERT — 13.7)
  • 입력: [CLS] 질문 [SEP] 지문 [SEP]
  • 지문의 각 토큰이 정답 구간의 시작(start)일 확률과 끝(end)일 확률을 각각 예측
  • 추출형이므로 정답은 반드시 지문 안의 연속된 구간(span)이어야 한다
데이터셋특징
SQuAD 1.1위키백과 지문 + 질문, 정답은 지문 속 구간
SQuAD 2.0지문에 정답이 없는 질문이 섞여 ‘정답 없음’을 판별해야 한다
KorQuAD 1.0한국어판 SQuAD
KorQuAD 2.0문서 전체(표 · 리스트 포함)를 지문으로 하는 긴 문서 기계독해

정답 구간 고르기 — s(i) + e(j)가 가장 큰 i ≤ j (교안 15p)

지문 토큰대한민국의수도는서울이다
start 점수 s0.5−1.00.2−1.02.0−0.5
softmax P(start)0.1420.0320.1050.0320.6370.052
end 점수 e0.1−1.00.3−1.01.80.6
softmax P(end)0.1000.0330.1220.0330.5470.165
🔎 손으로 구간 고르기 (점수는 설명용으로 정한 값) — 후보 구간 (i, j)마다 s(i) + e(j)를 더한다. (서울, 서울) = 2.0 + 1.8 = 3.8, (서울, 이다) = 2.0 + 0.6 = 2.6, (대한민국, 서울) = 0.5 + 1.8 = 2.3 … 가장 큰 것은 (서울, 서울) → 정답 “서울”. 소프트맥스는 각 줄을 합이 1인 확률로 바꿀 뿐 순위는 바꾸지 않는다(서울이 0.637 · 0.547로 1등). 지문 안의 연속 구간만 후보라 ‘지문에 없는 말’은 답이 될 수 없다 — 이것이 추출형의 뜻이다.
⚠ argmax 두 번 vs i ≤ j 제약 — 100문제 23번 보기는 ‘argmax P(start)부터 argmax P(end)까지’라고 쓴다. 위 예처럼 둘이 같은 자리를 가리키면 결과가 같다. 하지만 start 1등이 ‘서울’(5번째), end 1등이 ‘수도’(3번째)처럼 끝이 시작보다 앞에 오면 구간이 성립하지 않는다 — 그래서 교안 15p는 i ≤ j 이면서 s(i) + e(j)가 최대인 쌍을 고르라고 적었다. 실제 구현도 이 제약(과 최대 길이 제한)을 둔다.

EM과 F1 — 완전 일치 vs 부분 점수 (교안 16p)

  • EM(Exact Match) — 예측과 정답 문자열이 완전히 일치하는 비율(맞으면 1, 아니면 0)
  • F1 — 예측과 정답을 토큰 집합으로 보고 정밀도 · 재현율의 조화평균
  • 한 질문에 정답이 여러 개면 각 정답과의 점수 중 최댓값을 쓴다
사례정답예측EMF1계산
1서울서울1.01.00P = 1/1, R = 1/1
2서울대한민국 서울0.00.67토큰: P = 1/2(예측 2개 중 1개 맞음), R = 1/1 → 2·0.5·1/(0.5+1) = 0.667
3서울부산0.00.00겹치는 토큰 없음
🔎 표의 ‘문자 단위 0.50’ — 사례 2를 글자 단위로 세면 예측 ‘대한민국서울’ 6글자 중 정답 글자 ‘서 · 울’ 2글자가 겹쳐 P = 2/6 = 1/3, R = 2/2 = 1 → F1 = 2·(1/3)·1/(1/3 + 1) = 0.50. 같은 예측이라도 토큰을 무엇으로 자르느냐에 따라 점수가 달라진다 — 조사가 붙는 한국어(KorQuAD)는 글자 단위 F1을 함께 보고하는 이유다. F1은 부분 정답을 인정해 EM보다 관대하므로 두 지표를 함께 보고한다.
14.4

시각 질의 응답 (VQA)교안 17~20p

VQA — 사진을 보고 질문에 답하기 (교안 17p)

VQA = 자유 형식의 이미지와 그 이미지에 대한 다양한 질문이 주어졌을 때 올바른 답을 만드는 작업. 예: “who is wearing glasses?” — 비슷한 이미지라도 사진에 따라 “man” 또는 “woman”이 답이 되도록 데이터 분포를 고려한다(이미지를 안 보고 질문만으로 찍지 못하게).

이미지 캡셔닝VQA
출력이미지 전체를 묘사하는 문장질문이 지정한 대상 · 속성 · 관계에 선택적으로 집중한 답
필요한 능력이미지 이해이미지 이해 + 질문에 대한 통합적 추론

VQA 데이터 구성 — 개방형과 다지선다형 (교안 18p)

개방형 질문 유형예시 질문필요한 것
Fine-grained recognition (세밀한 인식)“피자 위에 올려진 치즈 종류는?”비슷한 것끼리의 미세한 차이
Object detection (물체 인식)“자전거가 몇 대나 세워져 있습니까?”물체를 찾아 세기
Activity recognition (행동 인식)“이 남자가 웃고 있습니까?”동작 · 표정
Knowledge base reasoning (지식 기반 추론)“이 피자는 채식주의자용인가요?”사진 밖 지식(고기 토핑 = 비채식)

VQA 기본 모델과 변형 (교안 19 · 20p)

이미지 → CNN(VGG 등)이미지 정보를 담은 벡터
질문 → word2vec 임베딩의 element-wise 평균(또는 LSTM) 질문 벡터
완전 연결층으로 같은 차원 → 결합(element-wise)두 벡터를 한 벡터로
MLP + Softmax → K개 정답 후보 확률정답을 ‘K개 중 하나 고르기’ 분류로 풀고 오차를 줄이도록 학습
모델특징
VQA 기본 모델위 흐름 — CNN + word2vec 평균, 결합 후 MLP · Softmax
다지선다형 모델선택지가 N개면 N번의 이진 분류를 하고 확률이 가장 높은 후보 선택
응용 모델이미지 임베딩은 AlexNet · VGGNet 등 사전학습 CNN 재사용, 텍스트는 word2vec · GloVe · LSTM, 결합은 element-wise 곱 · 덧셈 · concatenate
최근이미지 영역과 질문 단어 사이의 co-attention — 질문의 ‘안경’이 사진의 얼굴 영역을, 사진의 얼굴 영역이 질문의 ‘who’를 서로 참고
🔎 element-wise 결합을 숫자로 — 이미지 벡터 (0.8, 0.1, 0.5), 질문 벡터 (1.0, 0.0, 0.4)라면 element-wise 곱은 (0.8, 0.0, 0.2) — 둘 다 큰 칸만 살아남는다(‘질문이 묻는 것 AND 사진에 있는 것’). 덧셈은 (1.8, 0.1, 0.9)로 어느 한쪽만 커도 남고, concatenate는 6차원으로 이어 붙여 판단을 뒤 MLP에 맡긴다. 그래서 두 벡터를 먼저 같은 차원으로 맞추는 완전 연결층이 필요하다(곱 · 덧셈은 차원이 같아야 한다).

기계 번역의 소개와 발전 흐름교안 21~24p

기계 번역의 세 흐름 — 규칙 → 통계 → 신경망 (교안 22 · 23p)

기계 번역 = 소스 문장(Source Sentence)을 타겟 문장(Target Sentence)으로 컴퓨터가 번역하는 것.

규칙 기반 (RBMT)통계 기반 (SMT)인공신경망 (NMT)
방식언어학 · 문법 규칙 — 형태소 · 구문 분석 후 타겟 언어 문법 규칙에 맞게 변환대용량 코퍼스에서 배운 통계 정보로 번역딥러닝으로 입력 · 출력 문장을 하나의 쌍으로 두고 표현과 번역을 함께 학습
구성사전 + 규칙번역 모델(소스-타겟 alignment 추출) + 언어 모델(타겟 문장의 확률 예측)인코더-디코더(14.6)
장점규칙이 맞으면 정확, 설명 가능데이터가 많을수록 성능 향상문장 전체 문맥, End-to-End
한계규칙 구축 비용 큼, 새 언어쌍으로 확장 어려움수작업 자질 · 정렬 모델, 긴 문맥에 약함병렬 코퍼스 대량 필요
🔎 SMT의 두 모델을 한 문장으로 — “나는 학교에 갔다”를 번역할 때, 번역 모델은 ‘학교에 ↔ to school’, ‘갔다 ↔ went’ 같은 대응(alignment)과 그 확률을 병렬 코퍼스에서 센다. 언어 모델은 후보 “I went to school”과 “I to school went” 중 영어로 자연스러운 쪽의 확률을 높게 준다. 두 점수를 곱해 가장 높은 후보를 고른다 — 대응은 맞는데 어순이 이상한 번역을 언어 모델이 걸러 준다.

발전 순서와 실제 사례 (교안 24p)

통계 기반 (수작업 자질 · 정렬 모델)Word-based SMT → Phrase-based SMT → Hierarchical Phrase SMT
신경망 기반 (표현 학습 · End-to-End)RNN-based NMT → CNN-based NMT → Transformer-based NMT
  • 실제 응용: Google GNMT(Google Neural Machine Translation), Naver Papago
  • 2016년 이후 상용 번역 시스템 대부분이 NMT로 전환(RBMT로 간 것이 아니다 — 100문제 53번)
  • 현재는 트랜스포머 기반 대규모 다국어 모델(mBART, NLLB, LLM 계열)이 주류
14.6

Sequence to Sequence 구조와 인코더-디코더교안 25~28p

NMT = 문장 to 문장 (교안 25 · 26p)

  • NMT는 Sequence to Sequence 구조, 즉 문장 to 문장. 한-영 번역기 = “한국어 문장 to 영어 문장”
  • 학습에 필요한 것: Parallel Corpus(병렬 코퍼스) — 같은 뜻의 소스 · 타겟 문장 쌍
  • 인코더 = 인간의 언어를 컴퓨터가 이해할 수 있는 형태(벡터)로 바꾸는 것
  • 디코더 = 인코더 결과인 문장 임베딩 벡터와 이전 time-step까지 생성한 단어들에 기반해 현재 time-step의 단어를 생성
  • 기계 번역뿐 아니라 챗봇 · 요약 · 음성 인식에도 쓰인다
학습 기법 (교안 26p)내용
교사 강요 (Teacher Forcing)학습 때 디코더 입력으로 이전 예측 대신 실제 정답 단어를 넣어 학습을 안정화
특수 토큰문장의 시작 <sos>, 끝 <eos>
🔎 교사 강요가 왜 필요한가 — 정답이 “I went to school”인데 학습 초반 디코더가 첫 단어를 “You”로 틀렸다고 하자. 그 틀린 “You”를 다음 입력으로 넣으면 뒤의 단어들도 줄줄이 엉뚱한 문맥에서 배우게 된다. 교사 강요는 다음 입력으로 정답 “I”를 넣어 각 시점이 올바른 앞 문맥에서 배우게 한다 — 학습이 빠르고 안정적이다. 대신 추론 때는 정답이 없어 자기 예측을 넣어야 하므로, 학습과 추론의 입력이 달라지는 차이(노출 편향)가 생긴다.

동작 구조 — ‘나는 학교에 갔다’ → ‘I went to school’ (교안 27p)

인코더는 ‘나는 / 학교에 / 갔다 / <eos>’를 끝까지 읽어 문맥 벡터를 만들고, 디코더는 <sos>를 첫 입력으로 받아 ‘I’부터 ‘<eos>’가 나올 때까지 한 단어씩 만든다(100문제 61번). 교안 그림은 ‘to school’을 한 칸으로 묶어 그렸다.

RNN 기반 NMT의 문제점 (교안 28p)

문제왜해결
긴 문장 번역이 잘 안 됨문장 전체를 고정 길이 문맥 벡터 하나에 눌러 담는 정보 병목어텐션(14.7)
OOV 단어학습 데이터에 없는 단어는 생략하거나 잘못 번역서브워드(BPE) 토큰
앞부분 반복 번역어디까지 번역했는지 추적이 약함어텐션 정렬
학습 속도가 느림순차 처리 구조라 병렬화가 어려움트랜스포머
🔎 병목을 숫자로 — LSTM 은닉 크기가 256이면 문맥 벡터는 숫자 256개다. 5단어 문장이든 50단어 문장이든 똑같이 256칸에 담아야 하니, 50단어면 단어 하나당 약 5칸밖에 돌아가지 않는다. 게다가 마지막 상태는 최근 단어를 더 많이 기억해 문장 앞부분이 흐려진다. 어텐션은 인코더의 모든 시점 은닉 상태(50 × 256)를 디코더에게 넘겨 이 병목을 없앤다. 과제 5(14.9)가 바로 ‘어텐션 유무에 따른 BLEU 차이를 이 병목과 연결해 설명하라’이다.
14.7

어텐션 메커니즘과 트랜스포머 기반 번역 · BLEU교안 29~35p

어텐션 — 그때그때 어디를 볼지 정한다 (교안 29p)

  • 문제: 고정된 벡터 하나로 전체 맥락을 나타내면 긴 문장을 처리하기 어렵다 → 해결책이 Attention
  • 핵심: 어떤 시점에 어떤 부분에 집중할지 그때그때 동적으로 정하는 것
  • 인코더의 모든 스텝의 hidden state를 디코더에 넘겨준다 — 각 디코딩 스텝에서 입력의 어느 부분을 보는지 확인할 수 있다

어텐션 계산 4단계 (교안 30p)

단계식뜻
① Score\text{score}(s_t,h_i)디코더 상태와 인코더 상태의 유사도 — dot-product(Luong) · general · concat/additive(Bahdanau)
② Alignmenta_t=\text{softmax}(\text{score})합이 1인 가중치 분포
③ Contextc_t=\sum_i a_{t,i}\,h_i가중합 문맥 벡터
④ Output[c_t;\,s_t]\to\tanh\to\text{softmax}다음 단어 예측
🔎 ‘went’를 만들 때 한 번 계산해 보기 (값은 설명용) — 인코더 은닉 상태를 2차원으로 줄여 h나는 = (0.9, 0.1), h학교에 = (0.2, 0.8), h갔다 = (0.5, 0.5)라 하고, ① 점수가 (2.0, 0.5, 0.3)으로 나왔다고 하자. ② softmax → (0.711, 0.159, 0.130), 합 1. ③ 문맥 벡터 c = 0.711·(0.9, 0.1) + 0.159·(0.2, 0.8) + 0.130·(0.5, 0.5) = (0.737, 0.263) — 가장 큰 가중치를 받은 단어의 상태 쪽으로 끌려간다. ④ c와 디코더 상태 s를 이어 tanh → softmax로 다음 단어를 고른다. 디코딩 스텝마다 점수가 새로 계산되니 c도 매번 다르다 — ‘동적으로’의 뜻이다.

어텐션 전체 구조(교안 30p): Embedding(단어 → 벡터) → Bi-directional Encoder(양방향으로 각 시점 정보) → Attention(관심 있는 부분을 가중합해 결합) → Decoder(time-step별 단어 출력).

어텐션 가중치 시각화 (교안 31p)

출력 ↓ / 입력 →나는학교에갔다행 합
I0.820.100.081.00
went0.080.150.771.00
to school0.090.780.131.00

행 = 출력(타겟) 단어, 열 = 입력(소스) 단어, 진할수록 큰 가중치. 각 행의 합 = 1(softmax 결과). 어순이 다른 두 언어의 대응이 그대로 보인다 — 영어 2번째 단어 ‘went’는 한국어 3번째 ‘갔다’(0.77), ‘to school’은 ‘학교에’(0.78)를 본다. 행 합이 1이지 열 합이 1인 것은 아니다.

트랜스포머 — 순환 없이 어텐션만으로 (교안 32 · 34p)

“Attention Is All You Need”(2017)는 순환 구조를 제거하고 어텐션만으로 인코더-디코더를 만들었다. 모든 시점을 동시에 처리해 병렬 학습이 되고, 먼 단어 사이의 의존성도 한 번에 잡는다.

⚠ 디코더에만 있는 것 — Masked Multi-Head Attention과 Encoder-Decoder Attention(100문제 76번). Positional Encoding은 ‘순서 정보’, 미래를 가리는 것은 Masked Self-Attention이다 — 둘을 바꿔 놓은 보기가 함정(74번). 각 서브층 뒤에는 모두 Add & Layer Norm이 붙는다.

Scaled Dot-Product Attention과 √dk (교안 33p)

\text{Attention}(Q,K,V)=\text{softmax}\!\Big(\frac{QK^{\top}}{\sqrt{d_k}}\Big)V

질의(Q)로 키(K)를 검색해 값(V)을 가중합한다. 위 4단계의 Score = QKᵀ, Alignment = softmax, Context = ·V와 같은 일이다.

  • √dk로 나누는 이유 — Q · K의 각 성분이 독립이고 분산이 1이면 내적의 분산은 dk에 비례해 커진다 → 값이 커지면 softmax가 한쪽으로 포화되어 기울기가 거의 0 → √dk로 나누면 분산이 1 근처로 유지되어 학습이 안정된다
  • 멀티헤드 — dmodel을 h개로 나눠 각 헤드가 dk = dmodel / h 차원에서 따로 어텐션 → 이어 붙인 뒤 WO로 사영. 예: dmodel = 512, h = 8 → dk = dv = 64
  • 디코더의 마스킹은 미래 시점 스코어에 −∞를 더한다 → softmax 뒤 그 칸의 가중치가 정확히 0
🔎 √64 = 8의 효과를 숫자로 — dk = 64면 내적의 표준편차가 약 √64 = 8이다. 점수가 (8, 0, −8) 정도로 벌어지면 softmax는 (0.9997, 0.0003, 0.0000) — 사실상 한 칸만 1이라 다른 칸으로는 기울기가 흐르지 않는다. 8로 나눈 (1, 0, −1)이면 (0.665, 0.245, 0.090)으로 고르게 퍼져 모든 칸이 학습된다. 마스킹: 점수에 −∞를 더하면 e−∞ = 0이라 미래 단어 가중치가 정확히 0이 된다.

번역의 채점표 BLEU (교안 35p)

\text{BLEU}=BP\cdot\exp\Big(\sum_{n=1}^{4}w_n\log p_n\Big),\qquad BP=\min\big(1,\ e^{\,1-r/c}\big)

pn = 수정 n-gram 정밀도(후보의 n-gram 빈도는 참조에서의 최대 빈도까지만 센다 = clipping), c = 후보 번역 길이, r = 참조 번역 길이. 보통 wn = 1/4로 1~4-gram 정밀도의 기하평균. 범위 0~1(또는 0~100), 높을수록 참조와 비슷하다.

🔎 손으로 BLEU 한 번 — 참조 “the cat sat on the mat”(r = 6), 후보 “the cat sat on mat”(c = 5).
n후보의 n-gram참조에 있는 것pn
1the, cat, sat, on, mat5개 모두5/5 = 1
2the cat, cat sat, sat on, on maton mat 빼고 3개3/4 = 0.75
3the cat sat, cat sat on, sat on mat2개2/3
4the cat sat on, cat sat on mat1개1/2
기하평균 = (1 × 0.75 × 0.667 × 0.5)1/4 = 0.251/4 ≈ 0.707. 후보가 참조보다 짧으니 BP = e1 − 6/5 = e−0.2 ≈ 0.819. BLEU ≈ 0.819 × 0.707 ≈ 0.579. clipping이 없으면 “the the the”가 참조 “the cat” 앞에서 1-gram 정밀도 3/3을 받는다 — 참조에 the가 1번뿐이니 1번까지만 인정해 1/3. BP가 없으면 “the cat” 두 단어만 내놓아도 정밀도가 100%가 된다.
⚠ BLEU의 한계 — 표면적인 어휘 일치만 봐서 동의어 · 어순 변화를 반영하지 못한다(“I went to school” vs “I headed to school”). 그래서 METEOR · chrF · BERTScore · COMET을 함께 쓴다. r/c를 거꾸로 외우지 않기 — c = candidate(후보).

통계 언어모델의 한계와 자연스러운 문장의 조건 (교안 36p)

통계 기반 언어 모델자연스러운 문장 생성의 조건
장점: 해석이 쉽고 가볍다

순환 신경망 언어 모델 · LSTM 생성 (교안 37p)

P(w_t\mid w_1,\dots,w_{t-1})

이전 토큰들을 조건으로 다음 토큰의 확률을 예측한다. 이전 은닉층이 다음 은닉층에 영향을 주는 재귀 구조라 시계열(자연어 · 음성 · 유전자)에 쓰인다. LSTM 생성: 각 타임스텝의 이전 출력이 다음 입력이 되고, 게이트가 이전 정보를 선택적으로 반영한다(12주차 LSTM).

① 데이터 전처리코퍼스 수집 · 토큰화 · 어휘 사전 구축 · 시퀀스 생성 — 토큰 단위는 문자 / 단어 / 서브워드(BPE)에 따라 다르다

디코딩 전략 — 같은 모델, 다른 문장 (교안 39p)

디코딩 = 학습된 언어 모델의 확률 분포에서 실제 단어열을 만들어 내는 방법.

전략동작특징
Greedy Search매 스텝 확률 최고 토큰 1개빠르지만 반복 · 단조로운 문장
Beam Search상위 k개 후보 경로를 동시에 유지번역 · 요약에 적합, 다양성은 낮음
Temperaturelogit을 T로 나눠 분포를 평탄 / 뾰족하게T ↑ 다양성 ↑, T ↓ 보수적
Top-k Sampling확률 상위 k개 중에서만 샘플링엉뚱한 토큰 배제, k 선택이 중요
Top-p (Nucleus)누적 확률 p를 넘는 최소 집합에서 샘플링문맥에 따라 후보 수가 자동 조절

창작 · 대화에는 샘플링 계열, 번역 · 요약에는 beam search가 주로 쓰인다.

🔎 다섯 전략을 숫자로
  • Temperature — 다음 단어 후보 3개의 logit이 (2, 1, 0)일 때 softmax(logit/T): T = 1 → (0.665, 0.245, 0.090), T = 0.5 → (0.867, 0.117, 0.016)(1등이 더 독식, 보수적), T = 2 → (0.506, 0.307, 0.186)(평평, 다양). T → 0이면 greedy와 같아진다
  • Top-k — k = 2면 3등(0.090)을 버리고 1 · 2등을 다시 합 1로 맞춰 (0.731, 0.269)에서 뽑는다. k = 1이면 늘 1등만 뽑으니 greedy와 같다(과제 4의 질문)
  • Top-p — 확률이 (0.5, 0.2, 0.15, 0.1, 0.05)이고 p = 0.8이면 0.5 → 0.7 → 0.85에서 p를 넘으니 3개가 후보. 분포가 뾰족한 문맥(“대한민국의 수도는” 다음)에서는 1~2개, 평평한 문맥에서는 많이 — k를 고정하지 않아도 된다
  • Beam vs Greedy — 1단계 확률 A 0.5, B 0.4. A 다음 최고 0.4(누적 0.20), B 다음 최고 0.9(누적 0.36). greedy는 A를 고른 순간 0.20에 갇히지만, beam(k = 2)은 B 경로도 들고 가 0.36을 찾는다

QA 모델

공통: 각각 인코딩 → 연관성 점수 → 랭킹. 샴(가중치 공유) · 어텐션(질문 기준 답 단어 가중) · BiMPM 5층(Word → Context → Matching → Aggregation → Prediction).

BERT QA · 지표

[CLS] 질문 [SEP] 지문 [SEP], start · end 확률, i ≤ j에서 s(i) + e(j) 최대. SQuAD 2.0 = 정답 없음, KorQuAD 2.0 = 표 · 리스트 긴 문서. EM 0.0 · F1 0.67.

VQA

이미지 + 질문 → 답. 개방형 · 다지선다형, 5유형(세밀 · 물체 · 행동 · 지식 · 상식). CNN + word2vec 평균 → 결합 → MLP · Softmax(K개). 다지선다 = N번 이진 분류, 최근 co-attention.

기계 번역 흐름

RBMT(규칙, 확장 어려움) → SMT(번역 모델 = alignment + 언어 모델 = 타겟 확률) → NMT. Word → Phrase → Hierarchical SMT → RNN → CNN → Transformer NMT. 2016년 이후 NMT.

Seq2Seq

문장 to 문장, 병렬 코퍼스. 인코더 = 벡터로, 디코더 = 문맥 벡터 + 이전 단어로 현재 단어. 교사 강요, <sos> · <eos>. RNN 한계: 긴 문장(병목) · OOV · 반복 · 병렬화.

어텐션

모든 hidden state 전달. Score → Alignment(softmax, 합 1) → Context(가중합) → Output([c; s] → tanh → softmax). Luong(dot) · general · Bahdanau(additive). went → 갔다 0.77.

트랜스포머 · BLEU

softmax(QKᵀ/√d_k)V, 512 / 8 = 64. 디코더만 Masked · Enc-Dec Attention. BLEU = BP · exp(Σ w log p), BP = min(1, e^(1−r/c)), c = 후보, clipping.

문장 생성 · 디코딩

P(w_t | w_1…w_{t−1}). 전처리 → 설계 → 훈련 → 생성. greedy(단조) · beam(번역 · 요약) · T(↑ 다양) · top-k(k = 1 = greedy) · top-p(후보 수 자동). GPT = 디코더 전용, 환각, Medium 1024 · 24 · 345M.
