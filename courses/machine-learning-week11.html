11. 이미지 분류 — CNN으로 CIFAR-10을 분류하고, 유명한 모델 여섯을 훑는다

10주차에 흑백 숫자(28×28×1)로 CNN의 부품을 익혔다면, 이번 주는 컬러 사진(32×32×3)으로 넘어간다. 커널도 깊이 3을 갖게 되고, CIFAR-10을 7단계(읽기 → 전처리 → 구조 → 컴파일 → 학습 → 최고 가중치 → 평가)로 분류해 본다. 후반부는 VGGNet → ResNet → Inception → DenseNet → MobileNet → EfficientNet이 각각 무엇을 바꿨는지, 그리고 Top-5 · 민감도 · 특이도 · ROC/AUC 같은 평가 방법을 다룬다. 실습은 이미지 분류 모델의 하이퍼파라미터를 자동으로 찾는 KerasTuner다.

이번 주 한 줄 요약

  • 이미지 분류 = 미리 정한 카테고리 중 하나를 예측하고, 그 오차로 학습하는 것. 대표 모델은 CNN(합성곱 · 풀링으로 특징 추출 → FC로 분류)

  • CIFAR-10 분류 7단계: load_data → /255 정규화 · 원-핫 · 검증 5,000장 분리 → Conv 3번 + Dense 500 → compile(rmsprop) → fit + ModelCheckpoint → load_weights → evaluate. 파라미터 528,054

11.1

딥러닝 이미지 분류 개요와 CNN 개념교안 2 · 3 · 4p (교안 번호 9.1)

교안 슬라이드 모아보기 2 · 3 · 4p

교안예측 · 학습 · 테스트 (2 · 3p)

학습 목표는 하나다 — 딥러닝을 이용한 이미지 분류를 이해한다.

용어교안의 정의
딥러닝 모델 예측 과정영상을 딥러닝 모델에 입력하면 그 영상의 정답이 모델에서 예측되어 나오는 과정 — 숫자 영상 → 딥러닝 모델 → 예측된 결과
이미지 분류사전에 정의한 카테고리 안에서 예측을 수행하고, 오차를 이용해 모델을 학습하는 것
테스트학습된 모델로 (처음 보는) 이미지를 예측해 보는 작업

‘사전에 정의한 카테고리’가 핵심이다. CIFAR-10으로 학습한 모델은 사과 사진을 넣어도 10개 클래스(비행기 · 자동차 · 새 · …) 중 하나로 답한다. 물체의 위치까지 찾는 검출(14주차), 픽셀마다 클래스를 붙이는 분할(12주차)과는 다른 과제다.

교안CNN 개념 — 특징 추출과 분류 (4p)

이미지 분류의 대표 모델은 CNN이다. Convolution과 Pool 연산을 반복해 불변하는 특징(물체가 조금 옮겨지거나 커져도 그대로인 특징)을 찾고, 그 특징을 입력으로 Fully Connected layer에 보내 Classification을 한다.

Feature extractionImage → Convolution → Pool → Convolution — 10.5 · 10.6
Training and ClassificationFC (Fully Connected) layer → Classification — 10.7 전결합층

역할을 바꿔 외우면 틀린다 — 특징 추출 = 합성곱 · 풀링, 분류 = FC(100문제 12번).

11.2

컬러 이미지의 합성곱 연산과 CIFAR-10교안 5~8p

교안 슬라이드 모아보기 5 · 6 · 7 · 8p

교안컬러 이미지는 깊이 3, 커널도 3차원 (5~7p)

  • 10주차 CNN은 흑백(gray scale) 이미지를 픽셀값의 2차원 행렬로 다뤘다
  • 실제 컬러 이미지는 각 픽셀값이 원색의 강도이고, 너비 · 높이 · 깊이를 가진 3차원 행렬이다. RGB면 깊이 = 3(채널마다 하나)
  • 그래서 컬러 이미지 위를 움직이는 커널도 3차원이어야 한다 — 색상 채널별로 별도의 필터(필터의 면)가 있고, 각 면이 자기 채널 위를 움직이며 겹친 픽셀끼리 곱해 더한다
  • 세 채널의 값을 모아(합쳐) 특징 맵의 픽셀 하나를 만든다. 필터를 2개 쓰면 특징 맵도 2장이다(7p)

보충설명숫자로 해 보는 컬러 합성곱 한 칸

3×3 위치 하나에서 채널별로 ‘곱해서 더하기’를 한 결과가 R = 4, G = −1, B = 2이고 편향이 1이라고 하자.

\text{특징 맵 한 칸}=\underbrace{4}_{R}+\underbrace{(-1)}_{G}+\underbrace{2}_{B}+\underbrace{1}_{\text{편향}}=6\;\xrightarrow{\text{ReLU}}\;6

채널마다 특징 맵이 따로 나오는 것이 아니다 — 세 채널 결과를 더해 한 장이 된다(깊이 3 → 1). 필터 수가 출력 깊이를 정한다. 파라미터는 (k\cdot k\cdot C_{in}+1)\times C_{out}이므로 3×3 필터 32개면 (3\cdot3\cdot3+1)\times32=896이다(10주차 보충설명과 같은 식).

교안CIFAR-10 (8p)

컴퓨터비전 분야에서 널리 알려진 사물 인식 데이터셋이다. 32×32 컬러 이미지 6만 장, 10클래스 × 클래스당 6천 장 — airplane, automobile, bird, cat, deer, dog, frog, horse, ship, truck.

6만 장은 학습 50,000 + 테스트 10,000으로 미리 나뉘어 있다. 11.3에서 학습 50,000장 중 5,000장을 다시 검증용으로 떼어 낸다.

11.3

데이터 셋 읽기와 이미지 전처리 (1~2단계)교안 9~14p

교안 슬라이드 모아보기 9 · 10 · 11 · 12 · 13 · 14p

교안컬러 이미지 분류 7단계 (9p)

1 · 데이터 셋 읽어 들이기학습 / 검증 / 테스트로 분할 — 이 절
2 · 이미지 전처리정규화 · 원-핫 · 검증 분리 — 이 절

4 · 모델 컴파일손실 · 최적화 · 지표

6 · val acc가 높은 모델 사용load_weights

교안1단계 · 데이터 읽기, 2단계 · 정규화와 원-핫 (10~13p)

import keras
from keras.datasets import cifar10
(x_train, y_train), (x_test, y_test) = cifar10.load_data()  # 미리 무작위로 섞은 데이터를 학습 / 테스트로 분할해 준다

x_train = x_train.astype('float32')/255   # 픽셀값 구간 [0, 255] → [0, 1]
x_test  = x_test.astype('float32')/255    # 테스트에도 똑같이

num_classes = len(np.unique(y_train))    # 서로 다른 레이블 수 = 10
y_train = keras.utils.to_categorical(y_train, num_classes)   # 원-핫 인코딩
y_test  = keras.utils.to_categorical(y_test, num_classes)
  • 정규화: 문제와 데이터에 따라 다르지만 보통 학습 전에 데이터 클린징과 전처리를 거친다. 대표가 픽셀값을 0~1로 바꾸는 것이다. 학습 · 테스트에 같은 스케일을 적용해야 모델이 일관되게 동작한다
  • 원-핫 인코딩: 이미지마다 붙은 텍스트 레이블(dog, automobile, …)을 컴퓨터가 다룰 수 있는 숫자로 바꾼다. 해당 클래스 열만 1, 나머지는 0 — 13p 표에서 Image_1(dog)은 dog 열만 1이다
정정 · 주의 — 13p 코드 첫 줄 from keras.utils import np_utils는 지금의 Keras 3에는 없는 모듈이라 오류가 난다. 실제로 쓰는 것은 아래 줄의 keras.utils.to_categorical뿐이므로 그 줄은 지우면 된다. 또 CIFAR-10의 y_train은 이미 0~9 정수로 들어 있다 — ‘텍스트 → 숫자’ 단계는 끝나 있고, 원-핫은 ‘정수 → 길이 10 벡터’로 바꾸는 일이다.

교안훈련 · 검증 · 테스트 데이터 (14p)

데이터교안의 정의CIFAR-10에서
훈련모델을 학습하는 데 사용x_train[5000:] → 45,000장
검증훈련 데이터에 치우치지 않도록 하기 위한 별도의 데이터x_train[:5000] → 5,000장 (앞 5,000장)
테스트모델 성능을 최종 판단하기 위해 사용x_test → 10,000장
 
(x_train, x_valid) = x_train[5000:], x_train[:5000]
(y_train, y_valid) = y_train[5000:], y_train[:5000]

18p 학습 로그 첫 줄 ‘Train on 45000 samples, validation 5000 samples’가 이 분할의 결과다. 검증 세트는 학습에 쓰지 않고 에포크마다 성적표로만 본다 — 그래서 ‘가장 좋았던 에포크’를 고를 수 있다(6단계). 테스트는 마지막에 한 번만 본다.

11.4

모델 구조 정의 · 컴파일 · 학습 · 평가 (3~7단계)교안 15~21p · 36p (교안 번호 9.1 · 9.3)

교안 슬라이드 모아보기 15 · 16 · 17 · 18 · 19 · 20 · 21 · 36p

교안3단계 · 모델 구조 정의 (15 · 16p)

신경망 구조는 처음부터 새로 짜기보다 유명한 구조를 따라 만든 뒤 하나씩 바꿔 가며 영향을 분석한다. 여기서는 AlexNet의 간략 버전을 만든다.

model = Sequential()
model.add(Conv2D(filters=16, kernel_size=2, padding='same', activation='relu',
                 input_shape=(32, 32, 3)))       # input_shape 는 첫 합성곱층에만
model.add(MaxPooling2D(pool_size=2))
model.add(Conv2D(filters=32, kernel_size=2, padding='same', activation='relu'))
model.add(MaxPooling2D(pool_size=2))
model.add(Conv2D(filters=64, kernel_size=2, padding='same', activation='relu'))
model.add(MaxPooling2D(pool_size=2))
model.add(Dropout(0.3))                          # 과적합을 피하기 위한 드롭아웃 30%
model.add(Flatten())                             # 특징 맵 → 1차원 특징 벡터
model.add(Dense(500, activation='relu'))         # 첫 번째 전결합층
model.add(Dropout(0.4))                          # 두 번째 드롭아웃 40%
model.add(Dense(10, activation='softmax'))       # 출력층 10개 → 각 클래스의 확률
model.summary()

교안구현 포인트 두 가지 (36p, 교안 번호 9.3)

  1. 합성곱으로 뽑은 특징 맵을 분류할 수 있는 모양으로 바꾸는 과정 — 위 코드의 Flatten()(요즘은 전역 평균 풀링)
  2. 클래스 수에 맞춰 Output 크기를 정한다 — CIFAR-10이면 Dense(10), CIFAR-100이면 Dense(100)(100문제 55번)

교안4단계 · 컴파일 (17p)

설정교안의 정의코드
손실 함수학습 데이터를 대상으로 신경망의 성능을 파악하는 측정 수단loss='categorical_crossentropy' — 원-핫 레이블용 교차 엔트로피
최적화 알고리즘손실이 최소가 되도록 파라미터(가중치 · 편향)를 고치는 알고리즘optimizer='rmsprop'
평가지표학습 · 테스트 과정에서 모니터링할 지표metrics=['accuracy']

RMSprop은 6주차의 모멘텀 SGD처럼 경사하강법을 개선한 것으로, 파라미터마다 최근 기울기 크기의 이동 평균으로 학습률을 나눠 보폭을 자동 조절한다. Adam은 여기에 모멘텀을 더한 것이다(실습 코드는 Adam).

교안5단계 · 학습과 로그 읽기 (18 · 19p)

from keras.callbacks import ModelCheckpoint
checkpointer = ModelCheckpoint(filepath='model.weights.best.hdf5', verbose=1,
                               save_best_only=True)     # 좋아졌을 때만 저장
hist = model.fit(x_train, y_train, batch_size=32, epochs=100,
                 validation_data=(x_valid, y_valid), callbacks=[checkpointer],
                 verbose=2, shuffle=True)
  • loss · acc는 학습 데이터, val_loss · val_acc는 검증 데이터의 오차와 정확도다
  • 에포크마다 val_loss는 줄고 val_acc는 늘어야 한다. 학습 loss만 줄고 val_loss가 늘기 시작하면 과적합이다
  • 가장 좋았던 가중치는 그 에포크가 끝날 때 저장된다 — 로그의 ‘val_loss improved from 1.35820 to 1.22245, saving model…’

18p 로그를 읽어 보면: 1에포크 val_acc 0.5166 → 7에포크 0.6828로 오르다가, 8에포크는 ‘val_loss did not improve’(1.1300)로 저장되지 않았다. 학습 정확도(acc 0.66대)와 검증 정확도가 비슷하게 움직이므로 이 구간에서는 아직 과적합이 아니다.

교안6 · 7단계 · 최고 가중치 불러와 평가 (20 · 21p)

model.load_weights('model.weights.best.hdf5')    # 6단계 · 가장 좋았던 에포크의 가중치
score = model.evaluate(x_test, y_test, verbose=0)  # 7단계 · [손실, 정확도]

evaluate는 컴파일 때 지정한 순서대로 [손실, 지표]를 돌려준다 — score[0]이 손실, score[1]이 정확도다. 정확도는 ‘모델이 올바르게 예측하는 빈도의 백분율’이다.

정정 · 주의
  • ‘val acc가 높은 모델’이 아니라 ‘val loss가 낮은 모델’이다 — ModelCheckpoint의 기본 감시값은 monitor='val_loss'다. 18p 로그도 ‘val_loss improved … saving model’이다. val_acc 기준으로 고르려면 monitor='val_accuracy', mode='max'를 줘야 한다. 대개 둘이 같은 에포크를 고르지만 항상은 아니다
  • Keras 3에서는 파일 이름이 그대로 돌아가지 않는다 — 가중치만 저장하려면 save_weights_only=True와 이름 끝 .weights.h5(예: 'model.weights.best.weights.h5'), 모델 통째로면 .keras여야 한다. .hdf5는 옛 TensorFlow 2.x 시절 코드다

대표 CNN 아키텍처 (1) VGGNet · ResNet · Inception교안 22~29p (교안 번호 9.2)

교안 슬라이드 모아보기 22~29p

교안VGGNet — 3×3만으로 깊게 (23 · 24p)

  • 2014년 ILSVRC 2위, Oxford 대학교(Visual Geometry Group)의 모델
  • 깊이의 영향만 보려고 커널을 가장 작은 3×3으로 고정하고, 층 수만 바꾼 6가지 구성(A · A-LRN · B · C · D · E, 11~19층)을 실험했다
  • Keras Applications에서 VGG16으로 제공된다. 24p 코드: 3×3 Conv 블록 다섯 묶음 → Flatten() → Dense(4096, relu) × 2 → Dense(2, softmax)

24p 출력층이 2개인 것은 참조한 블로그 예제가 2클래스(개 / 고양이) 문제여서다. ImageNet용 원본은 1,000개다(23p 표의 FC-1000).

보충설명왜 3×3을 여러 번 쌓나

3×3 두 번을 거치면 출력 한 칸이 보는 입력 범위(수용 영역)가 5×5, 세 번이면 7×7이다(10주차 실습의 수용영역 5). 같은 범위를 보면서 파라미터는 적고, 층마다 ReLU가 들어가 비선형성은 더 많다.

\underbrace{3\times(3\cdot3\cdot C\cdot C)}_{3\times3\ \text{세 번}}=27C^2\quad\text{vs}\quad\underbrace{7\cdot7\cdot C\cdot C}_{7\times7\ \text{한 번}}=49C^2

대신 VGG16 전체 파라미터는 138,357,544개로 매우 크다(이 컴퓨터의 keras.applications.VGG16(weights=None)으로 확인). 그중 약 1억 2천만 개가 마지막 FC 세 층에 있다 — 이번 주 CIFAR 모델과 같은 이야기다.

교안ResNet — 지름길로 기울기를 살린다 (25~27p)

  • 2015년 ILSVRC 1위 (Deep Residual Learning for Image Recognition, CVPR 2016)
  • 연산량을 줄이기 위해 1×1을 결합한 block 제안 — 25p 표의 50층 이상 칸: 1×1(줄이기) → 3×3 → 1×1(늘리기) 병목 구조
  • 기울기 소실과 폭발을 해결하기 위해 Skip connect를 제안 — F(x)+x 뒤에 ReLU. 기울기 소실 = 층이 깊어질수록 경사가 사라지는 현상
  • 26p 코드: Identity block은 입력을 그대로 더하고(layers.add([x, input_tensor]) → ReLU), Conv block은 크기 · 채널이 바뀌므로 지름길에도 Conv2D(1×1, strides) + BN을 둔 뒤 더한다
  • 27p: conv_block 1개 + identity_block 여러 개를 stage 2~5로 쌓아 ResNet50을 만든다(3 · 4 · 6 · 3 블록)

보충설명지름길이 기울기를 살리는 이유 — 숫자로

y=x+F(x)를 미분하면 \dfrac{\partial y}{\partial x}=1+\dfrac{\partial F}{\partial x}다. 층마다 F의 기울기가 0.1밖에 안 된다고 하자.

층 20개를 지난 기울기계산값
지름길 없음0.1^{20}10^{-20} — 사실상 0 (기울기 소실)
지름길 있음(1+0.1)^{20}약 6.7 — 앞 층까지 신호가 간다

‘1 +’ 덕분에 F가 아무것도 배우지 못해도 최소한 입력이 그대로 전달된다. 그래서 152층도 학습된다. 반대로 F 기울기가 커서 곱이 폭발하는 문제는 BN(배치 정규화)이 함께 막는다. 10주차 실습의 BasicBlock이 바로 이 구조였다. ResNet50의 파라미터는 25,636,712개로 VGG16의 1/5이다.

교안Inception — 여러 크기 커널을 나란히 (28 · 29p)

  • 합성곱층의 커널을 개선해 연산 복잡도를 줄이고 파라미터 수를 적게 써서 파라미터와 속도를 함께 개선했다(Rethinking the Inception Architecture, CVPR 2016 = Inception v3)
  • Inception module로 채널 수를 조절할 수 있고 파라미터가 준다
  • 29p 코드: branch1x1 · branch5x5 · branch3x3dbl · branch_pool을 각각 만든 뒤 layers.concatenate([...], axis=channel_axis)로 채널 방향으로 이어 붙인다

한 층에서 1×1 · 3×3 · 5×5 · 풀링을 동시에 해 보고 결과를 모두 쓰는 셈이다 — 작은 물체 · 큰 물체를 같이 잡는다. 각 브랜치 앞의 1×1 합성곱이 채널 수를 먼저 줄여 연산을 아낀다(ResNet 병목과 같은 쓰임).

정정 · 주의 — 22p의 ‘RestNet’은 ResNet의 오타다. 또 22p 화살표는 연도 순서가 아니다 — 첫 Inception(GoogLeNet)은 2014년 ILSVRC 1위로, 같은 해 2위인 VGGNet보다 앞섰다. 교안의 Inception은 그 뒤 개량판인 v3(2015~2016)이다.
11.6

대표 CNN 아키텍처 (2) DenseNet · MobileNet · EfficientNet교안 30~35p (교안 번호 9.2)

교안 슬라이드 모아보기 30~35p

교안DenseNet — 앞의 모든 층을 이어 붙인다 (30 · 31p)

  • 모든 레이어의 특징 맵을 연결하는 방법(Dense block) — 각 층이 앞선 모든 층의 출력을 입력으로 받는다
  • 계속 이어 붙이면 채널 수가 많아지므로 층마다 만드는 특징 맵 수는 적게 쓴다
  • 31p 코드: dense_block(conv2 ~ conv5) 사이마다 transition_block(x, 0.5)를 두어 채널을 절반으로 압축하고 풀링으로 해상도를 줄인다

ResNet은 더하고(x+F(x), 채널 수 그대로), DenseNet은 이어 붙인다([x, F(x)], 채널 수 증가). 특징을 재사용하므로 DenseNet121은 파라미터 8,062,504개로 ResNet50의 1/3이다.

교안MobileNet — 합성곱을 두 단계로 쪼갠다 (32 · 33p)

  • 목표: 모바일 기기에서 서빙할 수 있는 가벼운 모델
  • Depthwise Convolution: 공간 방향으로, 특징 맵의 각 채널마다 다른 커널을 따로 쓴다(채널끼리 섞지 않는다)
  • Pointwise Convolution: 1×1 합성곱으로 채널 방향만 섞는다
  • Depthwise Separable Convolution = Depthwise + Pointwise

보충설명얼마나 가벼워지나 — 3×3, 32채널 → 64채널

방식가중치 수 (편향 제외)
일반 합성곱3\cdot3\cdot32\cdot64=18{,}432
Depthwise (채널마다 3×3 하나)3\cdot3\cdot32=288
+ Pointwise (1×1로 32 → 64)32\cdot64=2{,}048
Depthwise Separable 합계2,336 — 약 1/8

두 값 모두 Keras의 Conv2D · SeparableConv2D로 만들어 확인했다. 11.2의 일반 합성곱은 ‘공간 보기’와 ‘채널 섞기’를 한 번에 하는데, MobileNet은 이것을 둘로 나눠 곱셈을 크게 줄인다. MobileNet 전체 파라미터는 4,253,864개로 VGG16의 약 3%다.

교안EfficientNet — 깊이 · 너비 · 해상도를 함께 키운다 (34 · 35p)

모델을 키우는 세 방향 — 깊이(층 수) · 너비(채널 수) · 입력 이미지 크기(해상도) — 를 효율적으로 함께 조절하는 Compound Scaling을 제안했다.

\text{depth}: d=\alpha^{\phi}\qquad\text{width}: w=\beta^{\phi}\qquad\text{resolution}: r=\gamma^{\phi}

\alpha,\beta,\gamma는 작은 grid search로 한 번 정하는 상수이고, \phi는 쓸 수 있는 연산량에 따라 사용자가 정한다(100문제 92번). 원 논문의 값은 \alpha=1.2,\ \beta=1.1,\ \gamma=1.15이고 \alpha\cdot\beta^2\cdot\gamma^2\approx2로 맞춰, \phi를 1 올릴 때마다 연산량이 약 2배가 되게 했다. \phi=0인 기본 모델이 EfficientNetB0(파라미터 5,330,571개), 키운 것이 B1~B7이다.

정정 · 주의 — 35p 제목의 ‘EfficinetNet’은 EfficientNet의 오타다.

보충설명여섯 모델 한 표로 — 무엇을 바꿨나

교안 슬라이드 모아보기 37~41p

교안평가 방법 (37 · 38p)

지표교안쉽게
Confusion matrix이전 수업 자료에 기재정답 × 예측 표 — 4주차 · 6주차
Top-1 Accuracy가장 높은 1개의 정확도확률 1등 예측이 정답이면 맞음
Top-5 Accuracy가장 높은 5개의 정확도확률 상위 5개 안에 정답이 있으면 맞음 — 1,000클래스 ImageNet에서 주로 쓴다
Sensitivity (민감도)질병 있는 사람을 얼마나 잘 찾아내는가아픈 사람 100명 중 몇 명을 ‘아프다’고 했나

ROC Curve모든 임계값에서 분류 모델의 성능을 보여 주는 그래프가로 = 거짓 양성률(1 − 특이도), 세로 = 참 양성률(민감도). 왼쪽 위로 갈수록 좋다
AUCROC 곡선 아래 영역. 높을수록 클래스를 잘 구별1이면 완벽, 0.5면 동전 던지기

보충설명민감도 · 특이도를 숫자로

환자 100명(질병 20 · 정상 80)을 모델이 진단했다.

모델: 질병모델: 정상
실제 질병 20TP = 18FN = 2 (놓침)
실제 정상 80FP = 8 (오진)TN = 72
\text{민감도}=\frac{TP}{TP+FN}=\frac{18}{20}=0.90\qquad\text{특이도}=\frac{TN}{TN+FP}=\frac{72}{80}=0.90\qquad\text{정확도}=\frac{18+72}{100}=0.90

세 값이 같아 보여도 뜻이 다르다. 모든 사람을 ‘정상’이라고만 하는 모델도 정확도는 0.80이지만 민감도는 0이다 — 그래서 의료(10주차 MRI)처럼 놓치면 안 되는 문제는 민감도를 따로 본다. 임계값을 낮추면 민감도 ↑ · 특이도 ↓가 되고, 이 맞교환을 모든 임계값에 대해 그린 것이 ROC 곡선이다.

정정 · 주의 — 37p는 질병을 ‘(False)’, 정상을 ‘(True)’로 적었는데, 보통은 찾으려는 쪽(질병)을 양성(Positive)으로 둔다. 민감도 = 참 양성률(TP / 실제 양성), 특이도 = 참 음성률(TN / 실제 음성)이다. 시험(100문제 93 · 95 · 96번)은 교안 문구 그대로 ‘질병을 찾는 비율 = 민감도, 정상을 찾는 비율 = 특이도’로 고르면 된다.

정정 · 주의 — 데이터는 Fashion MNIST가 아니라 손글씨 숫자 MNIST다 — README는 ‘input : Fashion MNIST’라고 하지만, 폴더의 data/train-labels.idx1-ubyte 첫 레이블은 5, 0, 4, 1, 9, 2, …이고 첫 이미지는 숫자 ‘5’ 모양이다 — 원조 MNIST의 첫 열 장과 같다(Fashion MNIST라면 첫 레이블이 9(앵클 부츠)다). 파일 이름 · 형식이 같아서 생긴 혼동이다. 그래서 MLP 하나로 2에포크 만에 검증 정확도가 0.97까지 나온다.

1 · 데이터 준비 — 교안 1~2단계와 같은 흐름

x_train, x_val = x_train[:-10000], x_train[-10000:]      # 학습 60,000 → 50,000 / 검증 10,000 (뒤 1만 장)
x_train = np.expand_dims(x_train, -1).astype("float32") / 255.0   # (N, 28, 28, 1), [0, 1]
y_train = keras.utils.to_categorical(y_train, 10)          # 원-핫

교안(11.3)은 학습 데이터의 앞 5,000장을, 실습은 뒤 10,000장을 검증으로 뗐다 — 어느 쪽이든 학습 데이터 일부를 떼는 것은 같다. 로그의 ‘1563/1563’은 50,000 ÷ 배치 32 = 1,562.5 → 1,563스텝이다.

2 · 탐색 공간 정의 — build_model(hp)

코드뜻후보 수
hp.Int("units", 32, 512, step=32)은닉층 노드 수32, 64, …, 512 → 16개
hp.Choice("activation", ["relu", "tanh"])활성화 함수2개
hp.Boolean("dropout")Dropout(0.25)을 넣을지2개
hp.Float("lr", 1e-4, 1e-2, sampling="log")Adam 학습률연속값 — 로그 눈금에서 고르게(0.0001~0.001과 0.001~0.01이 같은 확률)

모델 구조는 Flatten → Dense(units) → [Dropout] → Dense(10, softmax)인 MLP다(합성곱 없음). 이산 조합만 16 × 2 × 2 = 64가지에 학습률은 연속이라, 전부 해 보지 않고 무작위로 몇 개만 뽑는다.

4 · 찾은 값으로 다시 학습

best_hps = tuner.get_best_hyperparameters(5)
model = build_model(best_hps[0])                  # 1등 조합으로 새 모델
x_all = np.concatenate((x_train, x_val))          # 검증 1만 장까지 합쳐 60,000장
model.fit(x=x_all, y=y_all, epochs=1)             # → accuracy 0.9085 (1에포크, 이 컴퓨터)

하이퍼파라미터를 고른 뒤에는 검증 세트가 더는 필요 없으니 합쳐서 다시 학습하는 것이 튜토리얼의 권장이다. 단, 이 코드는 x_test를 불러 놓고 한 번도 평가하지 않는다 — 교안의 7단계(evaluate)를 붙이면 최종 성능을 볼 수 있다: model.evaluate(x_test, y_test).

보충설명무작위 탐색 vs 격자 탐색, 그리고 왜 검증 세트로 고르나

  • 격자 탐색(Grid)은 모든 조합을 다 해 본다 — 64가지 × 학습률 몇 개 × 2회면 수백 번 학습이다. 무작위 탐색(Random)은 정해진 횟수만 뽑는다. 중요한 하이퍼파라미터가 한두 개뿐일 때 무작위가 같은 횟수로 그 축을 더 다양하게 시험한다(Bergstra & Bengio, 2012). KerasTuner에는 이전 결과를 보고 다음 후보를 고르는 BayesianOptimization, 짧게 많이 돌려 나쁜 것을 일찍 버리는 Hyperband도 있다
  • 하이퍼파라미터를 테스트 점수로 고르면 테스트에 맞춘 셈이 되어 최종 성능이 부풀려진다. 그래서 고르는 데는 검증, 마지막 보고에만 테스트를 쓴다 — 교안 11.3의 ‘검증 = 치우치지 않게, 테스트 = 최종 판단’이 바로 이 뜻이다
  • 교안 11.4 CIFAR 모델에 적용한다면: 필터 수(16 · 32 · 64), 커널 크기(2), 드롭아웃 비율(0.3 · 0.4), Dense 노드(500), 최적화(rmsprop)가 모두 hp.Int · hp.Choice · hp.Float로 바꿀 후보다
