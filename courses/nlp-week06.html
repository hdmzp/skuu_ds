6.1.1

자동 텍스트 요약이란교안 5~11p · 목적 · 입력 · 출력 세 각도로 보기

정의 — 자동 텍스트 요약은 원래 콘텐츠에 존재하는 모든 핵심 정보를 보존하면서 텍스트의 간결한 버전을 생성하는 과정이다. 교안이 드는 배경은 현실적이다 — 데이터가 크고 형태도 다양한데(문서 · 이메일 · 웹 페이지), 사람은 많은 양을 읽을수록 인내심이 줄고 ‘한 입 크기’로 소비하기를 선호한다.

압축률 (compression ratio)

\text{압축률}=\frac{\text{요약문 길이}}{\text{원문 길이}}

일반적으로 10~30% 수준을 목표로 한다(교안 6p). 너무 낮추면 정보가 빠지고, 너무 높으면 요약의 의미가 없다.

자동 요약이 주는 이점 다섯 가지 (교안 7p)

이점어떻게 쓰이나
샘플링기사를 공개하기 전 맛보기로 제공해 전체를 읽을지 결정하게 한다
검색검색 결과에 요약을 함께 보여 사용자가 고르기 쉽게 한다
인덱싱원본 대신 압축적 표현을 색인에 사용 — 저장 공간도 줄어든다
읽기 시간잘 만든 요약은 문서를 대신할 수 있다
질의 응답챗봇이 사용자 질문의 답으로 자동 요약을 제공한다

세 각도에서 보기 — 목적 · 입력 · 출력 (교안 8~11p)

목적
  • 일반적 요약 — 입력이 충분히 길면 다양한 도메인을 적절히 요약
  • 도메인 한정 요약 — 금융 · 쇼핑 · 의료 · 여행처럼 그 분야의 용어를 고려
  • 쿼리 기반 요약 — 사용자의 질문에 맞춰 요약
입력
  • 단일 문서 — 기사 · 이메일 · 긴 문서 하나. 요약 소프트웨어의 전형적 모드
  • 다중 문서 — 여러 문서를 모아 하나의 요약으로. 법률 회사가 여러 판례를 간추리는 식
출력
  • 추출적(extractive) — 원문의 문장을 그대로 골라 이어 붙임
  • 추상적(abstractive) — 의미를 이해한 뒤 새 문장을 생성
추출적 요약추상적(생성적) 요약
방식중요한 문장 · 구를 그대로 골라 이어 붙임의미를 이해한 뒤 새로운 문장을 만들어 냄
장점구현이 쉽고 문법 오류와 사실 왜곡이 거의 없다사람이 쓴 요약과 유사하고 압축률이 높다
단점문장 간 연결이 어색하고, 원문에 없는 표현으로 압축하지 못한다학습이 어렵고 환각(hallucination)으로 사실과 다른 내용을 만들 위험
“사실 왜곡이 없다”가 왜 큰 장점인가 — 법률 · 의료 문서에서는 없는 말을 지어내는 순간 쓸 수 없는 결과물이 된다. 추출 요약은 원문 문장을 그대로 쓰므로 원리적으로 환각이 불가능하다. 그래서 교안 42p의 결론도 “사실 왜곡이 절대 안 되는 분야 → 추출 요약 또는 추출+생성 하이브리드”다. 정확도가 아니라 실패했을 때의 비용으로 방법을 고르는 사고방식이다.
6.1.2

추출적 요약 — 문장에 순위를 매긴다교안 12~15p · 단어 빈도 · TF-IDF · 문장 유사도

핵심 원리는 하나다 — 텍스트의 문장들을 중요도별로 순위를 매기고, 상위 문장을 골라 요약을 구성한다. 문장의 중요도는 그 문장이 문서 전체의 의미에 얼마나 기여하는가로 해석한다. 알고리즘은 여러 가지지만 모두 이 원리를 공유한다.

순위 기준 세 가지

기준아이디어주의할 점
단어 빈도문서에서 자주 쓰인 단어가 많이 든 문장이 전체 의미를 대표한다불용어를 반드시 제거해야 한다 — 안 그러면 ‘the’가 많은 문장이 1등이 된다
TF-IDF 가중치흔한 단어의 기여를 깎고 그 문서다운 단어에 큰 가중치를 준다교안 6주차의 TF 정의가 5주차와 다르다 — 아래 ⚠ 참고
문장 유사도다른 문장들과 두루 닮은 문장이 문서의 중심 내용을 담고 있다n개 문장이면 n × n 유사도 행렬이 되고, 이것이 곧 TextRank 그래프의 가중치가 된다
TF의 정의가 주차마다 다르다
  • 5주차 — TF = 등장 횟수(원시 빈도) 그대로, IDF = \log\frac{1+N}{1+\mathrm{df}}+1 (scikit-learn 기본식)
  • 6주차 교안 — TF = \dfrac{\text{등장 횟수}}{\text{문서의 총 단어 수}}(상대 빈도), IDF = \log\dfrac{N}{1+\mathrm{df}}+1
교안 14p가 직접 “5주차는 TF를 원시 빈도로 정의하므로 값의 스케일이 다름”이라고 각주를 달아 두었고, 67p에서도 “이 손계산은 6주차 판 공식이며 TfidfVectorizer는 sklearn 기본식(+L2 정규화)이라 값이 다르다”고 못박는다. 시험에서는 어느 쪽 식으로 계산하라는 것인지부터 확인할 것.

문장 유사도 — 왜 유클리드 거리가 아니라 코사인인가 (교안 15p)

\cos(\mathbf{u},\mathbf{v})=\frac{\mathbf{u}\cdot\mathbf{v}}{\lVert\mathbf{u}\rVert\,\lVert\mathbf{v}\rVert}

문장이 길어지면 벡터의 크기가 커지지만 ‘내용’은 같을 수 있다. 코사인은 크기를 정규화하므로 길이의 영향을 받지 않는다 — 5주차 5.3.2에서 본 그대로다. 값의 범위는 −1~1이지만 임베딩 성분이 모두 양수면 0~1이 된다.

실습에서 확인한 것 — 같은 기사(A1)에 세 방법을 적용하면 고르는 문장이 서로 다르다. 
빈도 기반   → 문장 [0, 7, 8] 선택
TF-IDF     → 문장 [1, 2, 5] 선택
TextRank   → 문장 [0, 3, 8] 선택
세 방법 모두 “중요한 문장”을 고르지만 ‘중요하다’의 정의가 달라 결과가 갈린다. 어느 쪽이 좋은지는 6.1.5의 ROUGE로 재야 한다.
6.1.3

추상적(생성적) 요약교안 16~20p · seq2seq · 인코더-디코더 · 어텐션 · 사전학습 모델

추상적 요약은 원문의 문장을 그대로 옮기는 대신 의미를 재구성해 새 문장을 생성한다(원문 어휘를 재사용할 수는 있다). 본질적으로 원문을 더 간결한 형태로 다시 쓰는 일이라, 원문의 의미를 먼저 학습해야 해서 알고리즘을 만들기가 훨씬 어렵다.
① 시퀀스 투 시퀀스로 보기입력 텍스트는 단어들의 시퀀스, 요약은 출력 시퀀스. 요약은 결국 시퀀스를 다른(더 짧은) 시퀀스로 바꾸는 문제다
② 인코더-디코더인코더가 입력 시퀀스를 문맥 벡터로 압축하고, 디코더가 그것을 받아 출력 단어들을 만든다
③ 정보 병목과 어텐션입력이 길어지면 고정 길이 문맥 벡터 하나에 다 담기 어렵다(정보 병목). 그래서 디코더가 출력 단어를 만들 때마다 입력의 어느 부분을 볼지 고르는 어텐션을 쓴다
④ 트랜스포머순환 구조 없이 셀프 어텐션만으로 문맥을 파악해 병렬 학습이 가능 — 오늘날 추상 요약의 사실상 표준

어텐션 (교안 19p)

\mathrm{Attention}(Q,K,V)=\mathrm{softmax}\!\left(\frac{QK^{\mathsf T}}{\sqrt{d_k}}\right)V

질의(Query)와 키(Key)의 유사도로 가중치를 만들고 값(Value)을 가중합한다. 기계학습특론 5주차에서 본 “입력마다 달라지는 가중합”과 같은 식이다.

실무에서 쓰는 사전 학습 요약 모델 (교안 20p)

모델사전 학습 방식특징
BART원문을 일부 손상시킨 뒤 복원하도록 학습인코더-디코더 구조 · 요약에 강함
T5모든 과제를 text-to-text로 통일summarize: ... 형태의 프롬프트를 쓴다
PEGASUS문서에서 중요한 문장을 통째로 가린 뒤 복원요약에 특화된 사전 학습
한국어—KoBART · KoT5 등 공개 모델
 
from transformers import pipeline
summarizer = pipeline('summarization', model='facebook/bart-large-cnn')
summarizer(text, max_length=120, min_length=40)   # 3줄이면 끝난다
PEGASUS의 사전 학습이 특별한 이유 — BART는 “망가진 문장 복원”이라는 일반적인 과제로 학습하지만, PEGASUS는 문서에서 가장 중요한 문장을 통째로 가리고 그것을 복원하게 한다. 이 과제 자체가 “중요한 문장을 만들어 내는 일”이라 요약과 거의 같다. 사전 학습 과제를 실제 목표에 가깝게 설계할수록 적은 미세조정으로도 잘 된다는 것이 이 모델의 교훈이다.
6.1.4

TextRank — PageRank로 문장 순위를 매긴다교안 21~36p · 100문제에서 가장 비중이 큰 절(20문항)

TextRank는 추출적 요약에 널리 쓰이는 알고리즘으로 PageRank에 기반한다. PageRank는 구글이 검색 결과를 정렬할 때 가장 먼저 쓴 알고리즘인데, 핵심은 단순한 링크 개수가 아니라 그 페이지를 참조한 페이지들의 중요도를 가중해 재귀적으로 순위를 정한다는 것이다. TextRank도 똑같이 “중요한 문장과 많이 닮은 문장”을 다시 중요하게 본다. 비지도 방식이라 정답 요약 데이터가 없어도 바로 쓸 수 있다는 점이 가장 큰 장점이다.

여덟 단계 (교안 22 · 23p)

1~2. 문장 분리문서에서 텍스트를 읽어 문장 단위로 나눈다
3~4. 문장 벡터각 단어를 사전 학습 단어 벡터(GloVe 등)로 바꾸고, 그 평균으로 문장 벡터를 만든다
5~6. 유사도 행렬 → 그래프문장 사이 코사인 유사도로 n × n 행렬을 만들고, 이를 인접 행렬로 삼아 가중 그래프를 만든다
7~8. PageRank → 요약그래프에 PageRank를 적용해 점수를 구하고, 상위 n개 문장을 원문 순서대로 배열해 요약을 만든다

TextRank 점수 계산식 (교안 24p)

WS(V_i)=\frac{1-d}{n}+d\sum_{j}\frac{w_{ij}}{\sum_k w_{jk}}\,WS(V_j)

V_i는 문장 i를 나타내는 노드, w_{ij}는 문장 i와 j의 코사인 유사도, d는 감쇠 계수(damping factor)로 보통 0.85를 쓴다. 원 논문은 앞 항이 (1-d)이고 networkx는 (1-d)/n이다 — 교안이 이 차이를 각주로 밝혀 두었다. 점수 벡터가 수렴할 때까지 반복(멱승법)하며, networkx.pagerank()가 이 계산을 대신해 준다.

식을 말로 풀면 — 한 문장의 점수는 자기를 가리키는 문장들의 점수를, 그 문장과 얼마나 닮았는지로 가중해 모은 값이다. w_{ij}/\sum_k w_{jk}는 “문장 j가 가진 점수를 이웃들에게 나눠 줄 때 i의 몫이 얼마인가”를 뜻한다. 닮은 정도가 클수록 더 많이 받는다. 감쇠 계수 d는 “그래프를 계속 따라갈 확률”이다. 원래 PageRank에서 웹서핑하는 사람이 d의 확률로 링크를 타고, 1-d의 확률로 아무 페이지로 점프한다는 모형에서 나왔다. 점프 항이 없으면 고립된 묶음에 점수가 갇혀 수렴하지 않는다.

  • 출력 순서 — 점수 상위 n개를 고른 뒤 반드시 원문 순서로 되돌려 이어 붙여야 읽을 수 있는 요약이 된다(교안 36p의 sorted(top))
6.1.5

요약 품질 평가 — ROUGE교안 37~42p · 정답이 하나로 정해지지 않는 문제를 어떻게 채점하나

출발점 — 요약에는 ‘정답’이 하나로 정해지지 않는다. 사람마다 좋은 요약이 다르다. 그래서 평가가 둘로 나뉜다. 내재적(intrinsic) 평가는 사람이 쓴 참조 요약과 얼마나 겹치는지(ROUGE · BLEU)를 보고, 외재적(extrinsic) 평가는 요약을 쓴 후속 작업(검색 · 분류)의 성능으로 간접 측정한다.

ROUGE = Recall-Oriented Understudy for Gisting Evaluation

\text{ROUGE-N}_{\text{recall}}=\frac{\text{겹치는 n-gram 수}}{\text{참조 요약의 n-gram 수}},\qquad \text{ROUGE-N}_{\text{precision}}=\frac{\text{겹치는 n-gram 수}}{\text{생성 요약의 n-gram 수}}

ROUGE-1은 단어(unigram) 중복 — 내용어를 잘 담았는가. ROUGE-2는 바이그램 중복 — 표현이 자연스럽게 이어지는가. ROUGE-L은 최장 공통 부분 수열(LCS) 기반이라 어순을 반영한다.

교안 39p의 예제를 실습에서 그대로 검증 
참조 : the cat was found under the bed   (unigram 7개)
생성 : the cat was under the bed         (unigram 6개, 겹치는 것 6개)

ROUGE-1 Recall    = 6/7 = 0.857   (기대값 0.857)
ROUGE-1 Precision = 6/6 = 1.000   (기대값 1.000)
ROUGE-1 F1        =      0.923   (기대값 0.923)

ROUGE-L도 같은 문장으로 계산하면 LCS = “the cat was under the bed”(길이 6)이라 R_{lcs}=6/7=0.857이다. LCS는 연속일 필요가 없고 순서만 유지되면 되므로 문장 구조의 유사성을 본다.

6.2.1

마르코프 체인과 n-gram 언어 모델교안 44~51p · 가장 단순한 생성 모델

마르코프 체인은 확률에 기반한 상태 전환의 수학적 시스템이다. 어떤 시스템이 어떻게 현재 상태에 도달했든 상관없이 가능한 미래 상태는 사전에 정해져 있고, 다음 상태로의 이동은 확률에 따른다.
P(w_t \mid w_1,\dots,w_{t-1})\;\approx\;P(w_t \mid w_{t-1})
이것이 마르코프 가정이다 — “바로 앞 단어만 보면 충분하다”고 가정해 계산을 가능하게 만든다.

교안 46p의 상태 전이 확률 예제

코퍼스 — “나는 밥을 먹었다 / 나는 빵을 먹었다 / 나는 밥을 남겼다”

P(\text{밥을}\mid\text{나는})=\tfrac{2}{3}\approx 0.67,\quad P(\text{빵을}\mid\text{나는})=\tfrac{1}{3}\approx 0.33,\quad P(\text{먹었다}\mid\text{밥을})=P(\text{남겼다}\mid\text{밥을})=0.5

생성은 간단하다 — 시작 단어를 고른 뒤 위 확률에 따라 다음 단어를 무작위로 뽑는 과정을 반복한다.

n-gram 언어 모델 (교안 47p)

P(w_1\dots w_n)=P(w_1)P(w_2\mid w_1)\cdots P(w_n\mid w_1\dots w_{n-1}) \;\xrightarrow{\;\text{n-gram 근사}\;}\; \prod_t P(w_t \mid w_{t-n+1}\dots w_{t-1})

연쇄 법칙으로 쓴 정확한 식을, 직전 (n−1)개 단어만 본다고 근사한 것이 n-gram이다. 바이그램은 P(w_t\mid w_{t-1})=\dfrac{\mathrm{count}(w_{t-1},w_t)}{\mathrm{count}(w_{t-1})}로 센다. 마르코프 체인 텍스트 생성 = 바이그램 언어 모델이라고 보면 된다.

실습 — 기사 5편(795토큰, 고유 396개)으로 만든 전이 확률 
P(다음 단어 | 'the') 상위    court 4/53 = 0.075 · courts 2/53 · tour 2/53 · women 1/53
P(다음 단어 | 'tennis') 상위  players 1/4 · match 1/4 · matches 1/4 · and 1/4

‘the’ 뒤에는 53가지가 올 수 있지만 ‘tennis’ 뒤에는 4가지뿐이다. 코퍼스가 작을수록 뒤쪽 단어의 선택지가 급격히 줄어든다 — 이것이 바로 다음 문제다.

후보가 1개뿐이라는 것은 그 상태에서는 원문을 그대로 복사하는 것 말고 할 수 있는 일이 없다는 뜻이다. 5-gram이면 사실상 원문을 외워 뱉는 기계가 된다. 교안 51p가 정리한 마르코프 체인의 한계가 이것이다 — ① 문맥이 직전 한두 단어뿐이라 문장 전체의 일관성이 없다 ② 학습 데이터에 없던 조합은 절대 생성하지 못한다 ③ 단어를 기호로만 다뤄 ‘고양이’와 ‘고양이들’을 전혀 다른 상태로 본다 ④ n을 키우면 필요한 데이터가 지수적으로 증가한다.
해결의 실마리는 이미 교안에 적혀 있다 — “단어를 연속적인 벡터로 표현하고, 더 긴 문맥을 신경망으로 압축하기”(51p). 앞의 절반은 6.3의 임베딩, 뒤의 절반은 6.2.2의 신경망 언어 모델이다. ‘고양이’와 ‘고양이들’이 가까운 벡터가 되면 한쪽에서 배운 것이 다른 쪽에도 쓰이므로 데이터 희소성이 크게 완화된다.

신경망 언어 모델과 디코딩 전략교안 52~56p · NNLM → RNN → 트랜스포머, 그리고 무엇을 고를 것인가

NNLM (2003)단어를 임베딩 벡터로 바꾼 뒤 신경망으로 다음 단어를 예측 — 희소성 문제 완화
RNN · LSTM · GRU은닉 상태로 임의 길이의 문맥을 누적 — 이론상 길이 제한이 없다. 단점은 순차 계산이라 병렬화가 어렵고 아주 긴 의존은 여전히 어렵다는 것
Transformer (2017)셀프 어텐션으로 모든 위치를 한 번에 참조 — 병렬 학습 + 장거리 의존
GPT 계열트랜스포머 디코더만 쌓은 자기회귀 언어 모델. 서브워드(BPE · SentencePiece) 토큰화로 미등록 단어 문제를 해결
학습 목표는 마르코프 체인과 본질적으로 같다 — “다음 토큰 예측”(교안 53p). 차이는 문맥의 길이(수천~수십만 토큰)와 표현의 방식(기호가 아니라 연속 벡터)뿐이다.

전략방식성격

  • 저작권 · 개인정보 — 학습 데이터 원문을 그대로 뱉을 수 있다 → 출력 필터링
교안의 결론이 분명하다 — “생성 결과는 초안이며 사람의 검토가 전제되어야 한다.”
6.3.1

인코딩과 원핫 인코딩교안 58~65p · 왜 벡터로 바꾸는가, 그리고 가장 단순한 방법

왜 벡터인가 (교안 60p) — 문자 · 단어 · 문장 · 구절 · 문서는 형태가 서로 달라 알고리즘에서 그대로 다룰 수 없다. 벡터로 바꾸면 ① 서로 다른 연산을 같은 방식으로 수행할 수 있고 ② CPU · GPU가 배치로 처리할 수 있어 성능이 올라간다. 교안의 표현대로 “NLP의 핵심은 텍스트를 숫자로 표현하는 간단한 트릭”이다.

인코딩 전체 지도 (교안 61p)

1. 문자 수준ASCII · 유니코드 코드포인트 — ‘A’ → 65
2. 위치 기반토큰이 처음 나타난 순서로 번호를 매김
3~4. 원핫 · 단어 수준 원핫어휘 크기 N의 벡터에서 자기 자리만 1
5. BoW · TF-IDF빈도 기반 문서 표현
6. 단어 임베딩Word2Vec · GloVe · FastText
7. 문서 벡터 · 문맥 임베딩Doc2Vec · SBERT · BERT

위로 갈수록 희소하고 의미를 담지 못하며, 아래로 갈수록 조밀하고 의미를 담는다. 이 한 줄이 6.3절 전체의 지도다.

원핫의 한계를 실습 수치로 
어휘 : ['나는','밥을','빵을','먹었다'] → 나는 [1,0,0,0] · 밥을 [0,1,0,0] · ...
cos(밥을, 빵을)  = 0.000
cos(밥을, 먹었다) = 0.000      # 서로 다른 단어는 무조건 0 — 의미의 가까움을 표현 못 함

기사 5편 전체를 원핫 행렬로 만들면
  745 x 394 = 293,530개 값, 그중 0이 아닌 값은 745개 (희소도 99.75%)
  float32 저장 시 1.1 MB  →  같은 정보를 100차원 임베딩으로 두면 0.28 MB

교안 64p가 말한 “어휘가 5만 개면 단어 하나가 5만 차원”이 작은 기사 5편에서도 이미 4배의 메모리 차이로 나타난다.

6.3.2

BoW와 TF-IDF로 문서 표현하기교안 66 · 67p · 5주차 내용의 재정리와 한 가지 함정

BoW는 문서에 등장한 단어의 개수만 세어 문서를 벡터 하나로 만든다(어순은 버린다). D1 = “나는 밥을 먹었다”, D2 = “나는 빵을 먹었다”, 어휘 = [나는, 밥을, 빵을, 먹었다]라면 D1 = [1,1,0,1], D2 = [1,0,1,1]. 한계는 그대로다 — 흔한 단어가 과대평가되고 어순과 의미를 담지 못한다. 그래서 TF-IDF로 흔한 단어의 가중치를 낮춰 ‘그 문서다움’을 강조한다.

실습 — BoW와 TF-IDF 중 무엇이 주제를 더 잘 가르나 
기사 쌍 10개를 '같은 주제 / 다른 주제'로 나눠 평균 코사인 유사도

표현        같은 주제   다른 주제    격차     비율
BoW        0.0905    0.0305   0.0599   2.96
TF-IDF     0.0607    0.0190   0.0417   3.20

두 표현 모두 같은 주제 쌍의 유사도가 더 높다 — 주제 구분 자체는 둘 다 된다. 그런데 절대 격차는 BoW가, 상대 비율은 TF-IDF가 더 크다.

“TF-IDF가 언제나 낫다”는 통념이 이 데이터에서는 성립하지 않는다 TF-IDF는 흔한 단어의 기여를 깎기 때문에 유사도 값 자체가 전반적으로 낮아진다. 그런데 문서가 5편뿐이라 IDF 추정이 매우 거칠다 — 어떤 단어가 ‘흔한지’를 5편으로 판단해야 하니 신뢰도가 떨어진다. 표현 방식의 우열은 통념으로 정하는 것이 아니라, 지표를 정해 직접 재 보아야 한다 — 실습 노트북이 이 문장을 결론으로 출력한다.
문서별 TF-IDF 상위 단어 (실습) — 값이 낮아도 무엇이 그 문서다운 단어인지는 정확히 집어낸다. 
[A1] sharapova, friends, courts, many, difficult, tennis, tour, players
[A2] injury, level, young, back, training, taught, better, came
[A3] line, players, calls, judges, number, around, tennis, system
[A4] systems, therefore, summary, summaries, readers, follow, editor
[A5] word, words, vectors, problem, different, meaning, large, models
6.3.3

단어 임베딩 — Word2Vec · GloVe · FastText교안 68~75p · 분포 가설에서 출발한다

목표를 먼저 정리하자 (교안 69p) — 원핫의 세 가지 한계(① 벡터가 매우 큼 ② 거의 전부 0 ③ 벡터 사이의 관계 정보 없음)를 고치려면, 다음 조건을 만족하는 표현이 필요하다. ① 더 적은 차원(보통 50~300)으로 압축 ② 의미 정보를 담을 것 ③ 다른 벡터와의 관계 정보를 포함할 것.

분포 가설 (Firth, 1957)

“단어의 의미는 그 주변에 함께 나타나는 단어들에 의해 결정된다.” 따라서 같은 문맥에 나올 단어를 예측하도록 학습하면 의미를 담은 벡터를 얻을 수 있다. 이 아이디어를 구현한 대표 알고리즘이 Word2Vec이다. 변환 과정은 단어 → 원핫 벡터 → (가중치 행렬 곱) → 임베딩 벡터이고, 그 가중치 행렬이 곧 학습 대상이다.

CBOW

주변 단어들로 가운데 단어를 예측. 학습이 빠르고 자주 등장하는 단어에 유리

Skip-gram

가운데 단어로 주변 단어들을 예측. 느리지만 희귀 단어 표현이 좋다

윈도우 크기

문맥의 범위 — 작으면 문법적, 크면 주제적 유사성을 학습한다

학습을 가능하게 만든 두 가지 트릭 (교안 72p)

① 네거티브 샘플링 — 출력층 소프트맥스는 어휘 크기만큼 계산해야 해서 매우 느리다. 그래서 정답 1개 + 무작위 오답 k개(보통 5~20)만 가지고 이진 분류 문제로 바꿔 학습한다. 어휘가 10만이어도 한 번에 보는 것은 수십 개뿐이다.

② 서브샘플링 — ‘the’ 같은 초고빈도 단어를 확률적으로 제거한다. 흔한 단어는 어차피 정보가 적은데 학습 시간을 독차지하기 때문이다.

모델핵심 아이디어강점
Word2Vec문맥 예측(CBOW · Skip-gram)단순하고 빠르다 — 분포 가설의 직접 구현
GloVe전체 코퍼스의 단어 동시 등장 행렬을 직접 분해지역 문맥 + 전역 통계를 결합. glove.6B.50d 같은 사전학습 벡터가 널리 공개되어 TextRank 실습에 바로 쓴다
FastText단어를 문자 n-gram의 합으로 표현 (‘apple’ → <ap, app, ppl …)미등록 단어(OOV)도 부분 문자열로 벡터를 만들 수 있고 형태가 복잡한 언어에 강하다
실습 — Skip-gram + 네거티브 샘플링을 직접 구현 
학습 문장 38개, 어휘 104개
  epoch 10/30  평균 손실 2.6549  →  epoch 30/30  평균 손실 2.4100

'tennis' 와 가까운 단어 : number 0.908 · tour 0.899 · match 0.881 · court 0.867
'summary' 와 가까운 단어 : models 0.936 · follow 0.930 · editor 0.919 · keep 0.907
'vectors' 와 가까운 단어 : large 0.877 · words 0.834 · different 0.811 · word 0.800

‘tennis’ 옆에 tour · match · court가, ‘vectors’ 옆에 words · word가 모인다 — 38문장만으로도 분포 가설이 작동하는 것이 보인다.

그런데 유추(analogy)는 실패한다 — 그리고 그게 정상이다 
player : players = word : ?   →  each 0.870 · problem 0.839 · words 0.801
tennis : court  = text : ?    →  any 0.921 · every 0.873 · produce 0.841
교안 74p의 \mathrm{vec}(king)-\mathrm{vec}(man)+\mathrm{vec}(woman)\approx\mathrm{vec}(queen) 같은 깔끔한 결과가 나오지 않는다. 첫 번째 예에서 정답 words는 3위에 겨우 들어왔고, 두 번째는 아예 의미 없는 단어들이다. 이유는 데이터 크기다 — 교안의 유추 예시는 수십억 단어로 학습한 벡터에서 나온 것이고, 실습은 795토큰 · 38문장이다. “임베딩이 의미를 담는다”는 성질은 데이터가 충분할 때 나타나는 성질이지, 알고리즘만 돌리면 저절로 생기는 것이 아니다. 같은 이유로 gensim Word2Vec과 직접 구현의 순위도 서로 다르다 — 초기화 · 네거티브 샘플링 난수 · 학습률 스케줄이 다르기 때문이며, 작은 코퍼스일수록 이 차이가 크게 보인다.
사전 학습 벡터를 가져다 쓸 때 (교안 75p) — 이것이 전이 학습의 가장 단순한 형태다. 고려할 것은 ① 학습 도메인(위키피디아 벡터를 의료 텍스트에 쓰면 성능이 떨어진다) ② 어휘 개수와 차원 수(50/100/200/300 중 과제와 자원에 맞게) ③ 문맥 윈도우 크기 · 대소문자 처리 · 토큰화 방식의 일치.

문서 벡터와 문맥 임베딩교안 76~78p · 6주차 전체를 한 줄로 잇는 마지막 절
