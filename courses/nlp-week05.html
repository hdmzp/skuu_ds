5.1.1

텍스트 수치화와 원-핫 인코딩교안 6~10p · 가장 단순한 표현과 그 세 가지 한계

단어 표현(Word Representation)이란 — 텍스트의 기본 단위인 단어를 컴퓨터가 연산할 수 있는 숫자 · 벡터로 바꾸는 모든 방법을 통칭한다. 단어 임베딩(Word Embedding), 단어 벡터(Word Vector)라고도 부른다.

좋은 단어 표현이 갖추어야 할 네 가지 조건 (교안 6p)

  • ① 의미가 비슷한 단어는 벡터 공간에서도 가까이 있어야 한다
  • ② 차원이 지나치게 크지 않아 계산과 저장이 효율적이어야 한다
  • ③ 새로운 문서에도 같은 규칙으로 변환할 수 있어야 한다
  • ④ 문서 전체(문장 · 문단)를 표현하는 데까지 확장 가능해야 한다
이 네 조건이 곧 이번 절의 채점표다 — 원-핫은 ①을 완전히 실패하고 ②도 나쁘다. BoW는 ②·④를 개선하지만 ①은 여전히 못 한다. TF-IDF는 중요도라는 정보를 더하고, 분산 표현(Word2Vec)에 와서야 ①이 해결된다.

원-핫 인코딩 — 자기 자리만 1

말뭉치에 등장하는 서로 다른 단어를 모아 어휘 사전을 만들고 각 단어에 정수 인덱스를 준 뒤, 길이 V의 벡터에서 자기 인덱스 자리만 1, 나머지는 0으로 채운다. 하나만 뜨겁다(hot)고 해서 원-핫이다.
단어인덱스원-핫 벡터 (V = 4)
나는0[1, 0, 0, 0]
자연어1[0, 1, 0, 0]
처리를2[0, 0, 1, 0]
배운다3[0, 0, 0, 1]

세 가지 한계 (교안 10p)

한계무슨 일이 일어나나실습에서 확인한 값
① 차원의 저주
Curse of Dimensionality		어휘 사전이 수만~수십만이면 벡터 길이도 그만큼. 거의 전부가 0인 희소 벡터(sparse vector)가 된다리뷰 200건만으로도 V = 322, 벡터 하나의 0 비율 99.689%, 전체를 저장하면 322 × 322 = 103,684개의 값
② 유사도를 표현 못 함서로 다른 단어의 원-핫 벡터는 항상 직교한다 — 1이 켜진 자리가 겹치지 않으므로 내적이 늘 0“영화”와 “작품”의 내적 = 0
③ 빈도 · 중요도 정보 없음몇 번 나왔는지, 그 문서에서 얼마나 중요한지 담을 자리가 없다→ 그래서 BoW와 TF-IDF가 나온다
왜 ‘항상’ 직교인가 — 두 원-핫 벡터 \mathbf{a}, \mathbf{b}의 내적은 \mathbf{a}\cdot\mathbf{b}=\sum_k a_k b_k인데, 1이 켜진 자리가 서로 다르면 모든 항이 1\times 0 또는 0\times 1이라 합이 0이다. 코사인 유사도는 내적을 크기로 나눈 값(5.3.2)이므로 이것도 0. 즉 원-핫으로는 어떤 두 단어도 “조금 비슷하다”가 성립하지 않는다 — 같거나(1) 완전히 다르거나(0) 둘뿐이다. 이 문제를 정면으로 푼 것이 분산 표현이다.
원-핫 vs 정수 인코딩 — “그냥 단어마다 번호(0, 1, 2, 3)를 주면 안 되나?” 숫자를 그대로 쓰면 모델은 번호의 크기 관계를 의미로 오해한다. ‘배운다(3)’가 ‘나는(0)’보다 3배 크다거나, ‘자연어(1)’와 ‘처리를(2)’이 이웃이라고 학습해 버린다. 원-핫은 모든 단어를 서로 같은 거리에 놓아 이 오해를 막는다 — 대신 그 대가로 유사도 정보까지 함께 버린다.
5.1.2

Bag of Words · DTM · N-gram교안 11~16p · 순서를 버리고 횟수만 세기, 그리고 일부를 되찾기

Bag of Words (BoW) — 단어의 순서는 무시하고 오직 출현 빈도에만 집중하는 문서 표현. 문서에 나온 단어를 모두 가방에 넣고 흔든 뒤 개수만 세는 것에 비유한 이름이다. ① 어휘 사전 만들기 → ② 문서마다 길이 V 벡터를 만들고 등장 횟수 기록 → ③ 문서 하나가 길이 V의 빈도 벡터가 된다.

문서 단어 행렬 (DTM, Document-Term Matrix)

여러 문서의 BoW 벡터를 행으로 쌓아 만든 행렬이다. 행 = 문서, 열 = 단어.

문서영화재미지루추천
D1 “영화 재미 영화”2100
D2 “영화 지루”1010
D3 “재미 재미 추천”0201
 
# scikit-learn 으로는 두 줄이면 끝난다
from sklearn.feature_extraction.text import CountVectorizer

corpus = ["영화 재미 영화", "영화 지루", "재미 재미 추천"]
vect = CountVectorizer()          # 어휘 사전 생성기
X = vect.fit_transform(corpus)    # 학습(fit) + 변환(transform)을 한 번에

print(vect.get_feature_names_out())  # ['영화' '재미' '지루' '추천']
print(X.toarray())                   # [[2 1 0 0] [1 0 1 0] [0 2 0 1]]
여기서 사고가 난다 — fit_transform은 학습 데이터에만 쓰고, 검증 · 테스트 데이터에는 반드시 transform만 쓴다. 검증 데이터로 fit을 다시 하면 어휘 사전이 바뀌어 열의 의미가 달라지고, 시험지의 답을 미리 보는 것과 같은 데이터 누수(data leakage)가 된다.

BoW의 한계 세 가지

  • ① 순서 정보가 완전히 사라진다 — “개가 사람을 물었다”와 “사람이 개를 물었다”가 같은 벡터가 된다. 부정 표현(“재미없다”)이나 어순이 중요한 문장에서 치명적이다
  • ② 흔한 단어가 큰 값을 차지한다 — “the”, “is”, “그리고”, “하다”는 거의 모든 문서에 많이 나오는데 단순 빈도만 보면 이들이 문서를 대표하는 것처럼 보인다
  • ③ 여전히 희소 행렬이며 어휘 사전 크기에 비례해 차원이 커진다

N-gram — 순서를 ‘조금’ 되찾는 방법

연속한 N개의 토큰을 하나의 단위로 묶어 어휘 사전을 만든다. N = 1이면 유니그램, 2면 바이그램, 3이면 트라이그램. 예) “이 영화 정말 재미없다” → 유니그램 {이, 영화, 정말, 재미없다} / 바이그램 {이 영화, 영화 정말, 정말 재미없다}. 바이그램을 쓰면 “정말 재미없다”라는 부정 표현이 하나의 자질로 보존된다.

5.1.3

TF-IDF교안 17~23p · “이 문서엔 자주, 다른 문서엔 드물게”를 가중치로

핵심 아이디어 — “어떤 문서에서 자주 등장하지만(TF ↑), 전체 문서 중에서는 드물게 등장하는(DF ↓) 단어일수록 그 문서를 대표하는 중요한 단어다.” BoW의 두 번째 한계(흔한 단어 과대평가)를 정면으로 고친 것이 TF-IDF (Term Frequency – Inverse Document Frequency)다.
기호이름뜻
\mathrm{TF}(t,d)Term Frequency문서 d에서 단어 t가 등장한 횟수
\mathrm{DF}(t)Document Frequency단어 t가 등장한 문서의 개수 — 횟수가 아니라 문서 수
\mathrm{IDF}(t)Inverse DFDF의 역수에 로그를 취한 값 — 흔할수록 작아진다

scikit-learn 기본식 (smooth_idf=True)

\mathrm{IDF}(t)=\log\!\left(\frac{1+N}{1+\mathrm{DF}(t)}\right)+1, \qquad \text{TF-IDF}(t,d)=\mathrm{TF}(t,d)\times \mathrm{IDF}(t)

N = 전체 문서 수. 분모의 +1은 DF = 0일 때 0으로 나누는 것을 막고, 분자의 +1은 모든 단어를 담은 가상의 문서 한 개를 더한 효과(smooth)다. 로그는 N이 커질 때 IDF가 지나치게 커지는 것을 억제한다. 모든 문서에 등장하면 \log 1+1=1로 최솟값 1이 된다.

왜 마지막에 L2 정규화를 하나 — TF-IDF 값을 그대로 두면 긴 문서일수록 모든 값이 커진다(등장 횟수가 많으니까). 그러면 내용이 같아도 길이가 다른 두 문서가 다른 벡터로 보인다. 각 행(문서 벡터)을 \lVert \mathbf{v}\rVert_2 = 1이 되도록 나누면 길이의 영향이 사라지고 방향(어떤 단어가 상대적으로 중요한가)만 남는다. 그래서 정규화된 TF-IDF 벡터끼리의 코사인 유사도는 그냥 내적이 된다 — 5.3.2에서 다시 만난다.
IDF 식이 교재마다 다르다 고전적인 식 \log(N/\mathrm{DF})는 모든 문서에 나오는 단어의 IDF를 정확히 0으로 만들어 그 단어를 완전히 지워 버린다. scikit-learn 기본식은 뒤에 +1이 있어 IDF의 하한이 1이다 — 불용어라도 0으로 소멸하지 않고 상대적으로 낮아질 뿐이다. 그래서 sklearn을 쓰더라도 불용어 제거와 max_df 설정은 여전히 필요하다(교안 23p). 100문제에서 “IDF의 최솟값은?”이 나오면 어느 식인지부터 확인할 것.

분산 표현 (Word2Vec 개요)교안 24~27p · 희소에서 조밀로, 그리고 다음 주차로

분산 표현(Distributed Representation) — 단어를 수십~수백 차원의 조밀한 실수 벡터(dense vector)로 표현한다. 근거는 분포 가설(Distributional Hypothesis): “비슷한 문맥에서 등장하는 단어는 비슷한 의미를 가진다.” 그래서 “강아지”와 “개”가 벡터 공간에서 가까이 놓이고, 벡터 연산으로 의미 관계까지 표현된다 — \mathrm{vec}(\text{왕}) - \mathrm{vec}(\text{남자}) + \mathrm{vec}(\text{여자}) \approx \mathrm{vec}(\text{여왕}).
CBOW
Continuous Bag of Words
  • 주변 단어들 → 중심 단어를 예측
  • 학습이 빠르고, 자주 등장하는 단어에 유리
Skip-gram
  • 중심 단어 → 주변 단어들을 예측
  • 학습은 느리지만 희귀 단어 표현에 유리

이후 GloVe(카운트 기반) · FastText(부분 단어로 OOV 완화)로 발전하고, 문맥까지 반영하는 BERT 계열로 이어진다(이후 주차).

왜 ‘희소 → 조밀’이 그렇게 큰 변화인가 — 희소 표현에서는 각 차원이 특정 단어 하나를 뜻한다(322번째 칸 = ‘영화’). 그래서 단어가 늘면 차원도 함께 늘고, 두 단어 사이에는 아무 관계도 없다. 조밀 표현에서는 하나의 차원이 특정 단어가 아니라 여러 단어가 나눠 쓰는 어떤 성질(예: ‘감정가’, ‘구체성’)에 가까워진다. 의미가 여러 차원에 나뉘어 분산되어 있다고 해서 ‘분산 표현’이다. 덕분에 300차원이면 단어가 10만 개여도 충분하고, 비슷한 단어는 비슷한 좌표를 갖는다 — 5.1.1의 조건 ①과 ②가 동시에 해결된다.
‘희소 → 조밀’을 아주 쉽게 — 같은 단어를 두 방식으로 적어 보면 희소(sparse)는 “칸은 엄청 많은데 대부분 비어(0) 있다”, 조밀(dense, 밀집)은 “칸 수는 적은데 모든 칸에 값이 차 있다”는 뜻이다. 실습 어휘 사전(V = 322)으로 ‘영화’와 ‘작품’을 적어 보자.

① 나이브 베이즈 (Naive Bayes)

베이즈 정리로 문서가 각 범주에 속할 확률을 계산하는 확률 모델. 모든 단어가 서로 독립이라고 “순진하게(naive)” 가정해 계산을 단순화한다.
P(c \mid d) \propto P(c)\prod_{w \in d} P(w \mid c)
P(c)는 범주의 사전 확률, P(w \mid c)는 범주 c에서 단어 w가 나올 확률이다. 가장 높은 확률의 범주를 답으로 고른다.
“독립 가정”은 사실 틀렸는데 왜 잘 되나 — “재미”와 “있다”가 독립일 리 없다. 그런데 분류는 확률의 정확한 값이 아니라 어느 범주가 더 큰가만 맞히면 된다. 독립 가정이 확률값을 왜곡해도 순위는 잘 보존되는 경우가 많아, 실제로는 기대보다 잘 작동한다. 또 하나 — 학습에서 한 번도 못 본 단어가 있으면 P(w \mid c)=0이 되어 곱 전체가 0이 된다. 그래서 모든 빈도에 \alpha를 더하는 라플라스 스무딩을 쓴다. 실습 과제 5가 바로 이 \alpha를 탐색하는 문제다.

② 로지스틱 회귀 (Logistic Regression)

입력 자질의 선형 결합에 로지스틱(시그모이드) 함수를 씌워 0~1 값을 얻고 이를 확률로 해석한다. 1에 가까우면 1로, 0에 가까우면 0으로 예측. 학습된 가중치를 보면 어떤 단어가 긍정 · 부정에 기여했는지 직접 확인할 수 있어 해석력이 매우 높고, 고차원 희소 벡터(TF-IDF)와 궁합이 좋아 텍스트 분류의 표준 기준 모델로 쓰인다.
“선형 결합에 시그모이드를 씌운다”는 게 정확히 무슨 작업인가 두 단계로 나눠 보면 간단하다. ① 점수를 매기고 → ② 그 점수를 확률로 바꾼다.

① 선형 결합 — 단어별 (TF-IDF 값 × 가중치)를 모두 더한 ‘점수’

z = w_1x_1 + w_2x_2 + \cdots + w_nx_n + b

x_i는 리뷰 안 단어 i의 TF-IDF 값, w_i는 그 단어의 가중치(긍정이면 +, 부정이면 −), b는 기본 점수. 문제는 z가 −∞ ~ +∞ 아무 값이나 나온다는 것 — 1.86점, −3.38점은 “긍정일 확률”로 읽을 수 없다.

② 시그모이드 함수에 통과시키기 — 어떤 점수든 0과 1 사이로 눌러 담는다

\sigma(z) = \frac{1}{1+e^{-z}}

‘씌운다’ = 계산된 z를 이 함수의 입력으로 넣어 나온 값을 쓴다는 뜻이다. z가 크면 e^{-z}가 0에 가까워져 결과가 1에, z가 매우 작으면 e^{-z}가 커져 결과가 0에 가까워진다. z=0이면 정확히 0.5.

④ 랜덤 포레스트 (Random Forest)

의사결정 트리는 각 노드가 하나의 질문이고, 답에 따라 다음 노드로 내려가 최종 범주에 도달하는 구조다. 랜덤 포레스트는 이런 트리를 여러 개 만든다 — 데이터와 자질을 무작위로 뽑아 서로 다른 트리를 여럿 만들고, 각 트리의 결과를 다수결 · 평균으로 종합한다. 이것이 배깅(Bagging)이다.

③ 서포트 벡터 머신 (SVM, Support Vector Machine)

교안 요약 — 마진 최대화, 고차원 희소 데이터에 강함.
마진 최대화가 무슨 뜻인가 긍정 리뷰(●)와 부정 리뷰(○)를 가르는 선은 여러 개 그을 수 있다. SVM은 그중 양쪽에서 가장 가까운 점까지의 거리(마진, margin)가 가장 넓은 선을 고른다. 그 가장 가까운 점들이 경계선을 ‘떠받친다’고 해서 서포트 벡터(support vector)라 부른다 — 나머지 점은 아무리 많아도 경계선에 영향을 주지 않는다.
  • 왜 넓은 여백이 좋은가 — 경계가 양쪽 데이터에서 멀리 떨어져 있으면 새 데이터가 조금 흔들려도 잘못 넘어가지 않는다 → 일반화 성능이 좋다
  • 왜 텍스트(희소 · 고차원)에 강한가 — 차원이 수만 개면 데이터가 공간에 드문드문 흩어져 있어 직선(초평면) 하나로 나뉘는 경우가 많다. 선형 SVM이 TF-IDF와 궁합이 좋은 이유다
  • 커널(kernel) — 직선으로 안 나뉘면 데이터를 더 높은 차원으로 옮겨 나눈다(RBF 커널 등). 텍스트에서는 보통 선형 커널로 충분하다
  • scikit-learn — from sklearn.svm import LinearSVC · LinearSVC(C=1.0).fit(X_train, y_train). 로지스틱 회귀와 달리 기본 출력이 확률이 아니라 경계로부터의 거리다

  • “실제 긍정” = 정답 라벨이 긍정인 리뷰 전부. 모델이 뭐라고 했든 상관없이 진짜로 긍정인 것만 모은다 → 혼동 행렬 첫 번째 줄 = TP + FN = 22 + 3 = 25개
  • “찾아낸” = 그 25개 중 모델이 “긍정”이라고 맞게 짚은 것 = TP = 22개
  • 재현율 = 22 ÷ 25 = 0.88 → “진짜 긍정 리뷰 100개가 있으면 88개는 잡아내고 12개는 놓친다”

실제 긍정 25개 — ● 찾아냄(TP) 22 · ○ 놓침(FN) 3 → 재현율 22/25 = 0.88

비유 — 그물로 물고기 잡기: 호수에 물고기(실제 긍정)가 25마리 있다. 그물을 던져 22마리를 건졌다면 재현율 88%. 그물에 같이 딸려 온 쓰레기(FP)는 재현율 계산에 아예 들어가지 않는다 — 그건 정밀도의 몫이다.

왜 하필 ‘조화’ 평균인가 — 산술 평균을 쓰면 한쪽이 1.0, 다른 쪽이 0.0일 때도 0.5가 나와 “절반은 한다”처럼 보인다. 조화 평균은 작은 쪽에 끌려간다 — 0과 1의 조화 평균은 0이다. 즉 F1은 정밀도와 재현율이 둘 다 높아야만 높아지는 지표라서, 한쪽을 희생해 다른 쪽을 올리는 꼼수를 막아 준다. 예를 들어 전부 ‘긍정’이라고 답하면 재현율은 1.0이 되지만 정밀도가 0.5로 떨어져 F1은 0.667에 그친다.
정확도의 함정 — 클래스 불균형 스팸이 전체의 1%인 데이터에서 “전부 정상”이라고만 답해도 정확도는 99%다. 그런데 이 모델은 스팸을 한 건도 못 잡았으므로 재현율은 0이다. 그래서 교안은 “클래스가 불균형할 때는 정확도만으로 판단하면 안 되며 혼동 행렬을 반드시 함께 확인하라”고 못박는다. 실습 데이터는 100 : 100이라 정확도를 그대로 믿을 수 있는 드문 경우다.

자카드 유사도 (Jaccard Similarity)

두 문장을 단어의 집합으로 만든 뒤

J(A,B)=\frac{\lvert A \cap B \rvert}{\lvert A \cup B \rvert}

0~1 값이며 1에 가까울수록 유사하다. 완전히 같으면 1, 공통 원소가 없으면 0. 벡터화가 필요 없고 계산이 매우 빠르다. 대신 단어의 등장 횟수(빈도)를 전혀 반영하지 못한다.

교안 56p 계산 — 조사까지 따로 토큰으로 두면 A = {휴일, 인, 오늘, 도, 서쪽, 을, 중심, 으로, 폭염, 이, 이어졌는데요, 내일, 은, 반가운, 비, 소식, 있습니다} (17개) B = {폭염, 을, 피해서, 휴일, 에, 놀러왔다가, 갑작스런, 비, 로, 인해, 망연자실, 하고, 있습니다} (13개) 교집합 = {휴일, 을, 폭염, 비, 있습니다} → 5개, 합집합 = 17 + 13 − 5 = 25개 → J = 5/25 = 0.20
같은 문장인데 값이 0.20과 0.167로 다르다 — 왜? 교안 56p는 0.20, 교안 63p 표와 실습 노트북은 0.167(공통 4개 / 전체 24개)이다. 틀린 것이 아니라 토큰화 기준이 다르기 때문이다. 실습의 간이 토크나이저는 어간 추출을 하고 조사를 다르게 잘라서 집합 자체가 달라진다(“있습니다” → “있”, “놀러왔다가” → “놀러왔” 등). 교훈 — 토크나이저가 바뀌면 유사도 값도 바뀐다. 그래서 유사도의 절대값을 비교할 때는 반드시 같은 전처리를 거쳤는지 확인해야 한다.
자카드 유사도는 언제 쓰나
  • 세부 비교보다는 전체적으로 크게 비교할 때 용이하다
  • 계산이 매우 빠르다
왜 ‘크게’ 비교하는 데 맞고, 왜 빠른가
  • 크게 비교한다 = “어떤 단어가 있었나 없었나”만 본다는 뜻. 몇 번 나왔는지(빈도), 그 단어가 얼마나 중요한지(가중치), 순서는 전부 무시한다. 그래서 “두 문서가 대체로 같은 재료로 이루어졌나”를 대략 가늠하는 데는 좋지만, “어느 쪽이 더 비슷한가”를 섬세하게 가리기엔 정보가 부족하다
  • 빠르다 — ① TF-IDF처럼 전체 말뭉치로 사전을 만들고 벡터화하는 단계가 없다(두 문장만 있으면 바로 계산) ② 계산이 곱셈 · 제곱근 없이 집합의 교집합 · 합집합 크기 세기뿐이다 ③ 파이썬 set은 해시 기반이라 원소 확인이 거의 즉시 끝난다
  • 실전 활용 — “1차 거르기” : 웹 문서 · 학습 데이터 수백만 건에서 거의 같은 문서(중복)를 찾을 때, 자카드를 근사하는 MinHash로 먼저 후보를 빠르게 추리고, 추려진 후보만 코사인 등으로 정밀 비교하는 2단계 방식이 표준이다. “크게 먼저, 세부는 나중에”의 전형이다
def jaccard(a, b):
    A, B = set(a), set(b)           # 토큰 리스트 → 집합 (중복 · 순서가 여기서 사라진다)
    return len(A & B) / len(A | B)  # & = 교집합, | = 합집합 — 이게 전부

jaccard(["영화","재미"], ["영화","영화","영화","재미"])   # → 1.0  빈도 차이는 못 본다

코사인 유사도 (Cosine Similarity)

두 벡터가 이루는 각도로 재는 유사도

\cos\theta = \frac{\mathbf{A}\cdot\mathbf{B}}{\lVert \mathbf{A}\rVert \, \lVert \mathbf{B}\rVert}

방향이 같으면 1, 직각이면 0, 정반대면 −1. TF-IDF 값은 항상 0 이상이므로 실제로는 0~1만 나온다. 문서의 길이(벡터 크기)에 영향을 받지 않는 것이 가장 큰 장점이라, 텍스트 유사도의 표준 척도로 쓰인다.

왜 길이에 강한가 — 교안 58p 예시를 실습으로 확인 
D1 : "영화 재미"           → [1, 1]
D2 : "영화 영화 재미 재미"  → [2, 2]     # 사실상 같은 내용, 길이만 2배

코사인          = 1.000   ← 방향이 같으므로 완전히 같다고 판정
유클리디언 거리  = 1.414   ← 길이가 다르다는 이유로 "멀다"고 판정
그런데 “길이에 영향을 받지 않는 것”이 왜 그렇게 중요한가? 현실의 문서는 길이가 제각각이기 때문이다. 한 줄 리뷰와 A4 세 장짜리 리뷰, 3단어짜리 검색어와 1,000단어짜리 문서를 비교해야 한다. 그런데 BoW · TF-IDF 벡터의 값은 단어를 셀수록 커진다 — 긴 문서는 내용이 같아도 벡터 크기(길이)가 커진다. 길이에 흔들리는 척도를 쓰면 “무슨 내용인가”가 아니라 “얼마나 길게 썼나”를 비교하게 된다. 
# 어휘 [영화, 재미, 지루] · 검색어 Q = "영화 재미"
Q        = [1, 1, 0]
B (긴 칭찬 리뷰)  = [5, 5, 1]    # 같은 이야기를 길게 — 주제가 Q와 같다
C (짧은 혹평)     = [1, 0, 1]    # 짧지만 주제가 다르다

             유클리디언 거리      코사인 유사도
Q ↔ B        5.745 (멀다?!)      0.990 (거의 같다)
Q ↔ C        1.414 (가깝다?!)    0.500
유클리디언은 짧은 혹평 C가 더 가깝다고 판정한다 — 단지 길이가 비슷하다는 이유로. 코사인은 단어 구성 비율(방향)만 보므로 B가 주제상 같다는 것을 제대로 잡아낸다.
  • 검색 — 질의는 짧고 문서는 길다. 길이에 흔들리면 긴 문서가 부당하게 불리(거리)하거나 유리(내적)해진다
  • 공정성 — 같은 내용을 길게 쓴 문서와 짧게 쓴 문서를 ‘같다’고 봐야 문서끼리 공정하게 순위를 매길 수 있다
  • 정보 검색 교과서의 표현 — 코사인은 “비교 과정에서 문서 길이를 정규화하는 방법”이다. 벡터를 길이 1로 맞춘 뒤(5.1.3의 L2 정규화) 내적하면 그게 곧 코사인이다
코사인의 두 가지 주의점 ① 단어가 하나도 겹치지 않으면 의미가 아무리 비슷해도 유사도는 0이다 (→ 5.3.4에서 실제 사례). ② 반대로 단어만 겹치면 뜻이 정반대여도 높게 나온다 — 실습에서 “이 영화는 재미있다” vs “이 영화는 재미없다”의 코사인이 0.603이었다.
자카드는 ‘무엇이 겹쳤나’, 코사인은 ‘얼마나 중요한 게 겹쳤나’ 자카드는 집합 연산이라 ‘그 단어가 있었나 없었나’만 본다. “영화 재미”와 “영화 영화 영화 재미”의 자카드는 1.0이다(집합이 같으니까) — 빈도 차이를 전혀 못 본다. 코사인은 TF-IDF 벡터를 쓰므로 흔한 단어가 겹친 것보다 드문 단어가 겹친 것을 더 높게 친다. 그래서 문서 비교에는 보통 코사인을, 단순 단어 중복 확인(예: 표절 1차 필터)에는 자카드를 쓴다. 실습 과제 4는 이 둘을 w\,J(A,B) + (1-w)\cos(\mathbf{v}_A,\mathbf{v}_B)로 섞는 하이브리드 유사도를 구현하는 문제다.
5.3.3

유클리디언 · 맨해튼 유사도교안 59~63p · 거리로 재면 정규화가 필요하다

유클리디언 거리 (L2) · 맨해튼 거리 (L1)

d_{L2}(A,B)=\sqrt{\sum_i (a_i-b_i)^2}, \qquad d_{L1}(A,B)=\sum_i \lvert a_i-b_i \rvert

거리이므로 값이 작을수록 유사하다 — 유사도와 방향이 반대다. 유사도로 쓰려면 \mathrm{sim}=1/(1+d) 같은 변환이 필요하다. 맨해튼은 대각선으로 가로지르지 않고 좌표축을 따라 이동한 거리라, 바둑판 모양 도시(맨해튼)에서 블록을 따라 걷는 것에 비유한 이름이다.

정규화가 필요한 이유 — 두 거리 모두 값의 범위에 제한이 없어 1보다 큰 값이 얼마든지 나온다. 제한이 없는 값은 다른 척도와 비교하기 어렵다. 그래서 각 문장 벡터를 L1 정규화(모든 성분의 합이 1이 되도록)한 뒤 거리를 계산한다. 성분이 0 이상이므로 정규화 후 유클리디언은 0~√2, 맨해튼은 0~2 범위가 된다.
L1 정규화와 L2 정규화 — 같은 벡터로 비교 ‘정규화(normalization)’는 벡터의 방향(비율)은 그대로 두고 크기만 1로 맞추는 것이다. “크기”를 무엇으로 재느냐에 따라 L1과 L2로 나뉜다.
L1 정규화L2 정규화
크기를 재는 법성분 절댓값의 합 \lVert v\rVert_1=\sum_i \lvert v_i\rvert성분 제곱합의 제곱근 \lVert v\rVert_2=\sqrt{\sum_i v_i^2} (화살표의 실제 길이)
정규화 후 조건모든 성분의 합이 1제곱합이 1 (길이가 1)
v = [3, 4] 예시합 = 3 + 4 = 7 → [3/7, 4/7] = [0.429, 0.571]길이 = √(9+16) = 5 → [0.6, 0.8]
해석“전체 중 몇 %” — 비율 · 확률 분포처럼 읽힌다“방향만 남긴 화살표” — 원 위의 점

L2 정규화와 코사인의 관계 — 두 벡터를 L2 정규화하면 d_{L2}^2 = 2(1-\cos\theta)가 성립한다. 즉 L2 정규화 뒤의 유클리디언 거리는 코사인과 순위가 완전히 같아진다 — 길이 문제를 정규화로 없앴기 때문이다.
맨해튼 유사도 — 손으로 한 번 계산 A = [0.5, 0.3, 0.2], B = [0.2, 0.3, 0.5] (둘 다 L1 정규화된 상태) 
차이        : |0.5−0.2| = 0.3,  |0.3−0.3| = 0,  |0.2−0.5| = 0.3
맨해튼 (L1) : 0.3 + 0 + 0.3            = 0.600   # 차이를 그냥 더한다
유클리디언  : √(0.3² + 0² + 0.3²) = √0.18 = 0.424   # 제곱해 더하고 루트
유사도 변환 : 1/(1+0.600) = 0.625,  1/(1+0.424) = 0.702
  • 차이 — 유클리디언은 차이를 제곱하므로 한 성분의 큰 차이를 더 크게 벌한다. 맨해튼은 모든 차이를 똑같이 더한다 → 튀는 값(이상치)에 덜 민감하다
  • 항상 맨해튼 ≥ 유클리디언 (0.600 ≥ 0.424) — 블록을 따라 도는 길이 직선보다 짧을 수 없다
  • 이름의 ‘유사도’ — 교안은 “맨해튼 유사도”라 부르지만 계산한 값 자체는 거리다. 작을수록 비슷하다

Q2BoW가 “개가 사람을 물었다”와 “사람이 개를 물었다”를 구분하지 못하는 이유는?
BoW는 단어를 가방(bag)에 넣고 “몇 개씩 들었나”만 세서, 단어의 순서(= 누가 누구를)를 버리기 때문이다. 
어휘 : [개, 사람, 물었다]          # 조사 ‘가 · 이 · 을 · 를’은 정제 단계에서 떨어진다
"개가 사람을 물었다"  → [1, 1, 1]
"사람이 개를 물었다"  → [1, 1, 1]     # 완전히 같은 벡터 → 실습에서도 True
의미를 결정하는 것은 “누가 주어이고 누가 목적어인가”, 즉 순서와 문법 관계인데 BoW는 그 정보를 담을 칸이 없다. 보완책 — N-gram(“개 사람” vs “사람 개”처럼 인접 쌍을 자질로 → 국소적 순서 복원), 더 나아가 순서를 입력으로 받는 RNN · Transformer. → 5.1.2
Q3IDF에 로그를 취하는 이유는 무엇인가?
N/DF 값이 문서 수에 따라 폭발적으로 커지는 것을 눌러, 희귀 단어의 가중치가 지나치게 커지지 않게 하려고. 문서가 100만 개인 말뭉치를 생각해 보자.

DF = 10           100,000         11.5
DF = 1,000        1,000            6.9
DF = 100,000      10               2.3
  • 로그가 없으면 — 한 번 나온 단어가 1,000,000, 흔한 단어가 10 → 10만 배 차이. 오타 하나가 문서 벡터 전체를 지배해 버린다
  • 로그를 씌우면 — 13.8 vs 2.3 → 6배 차이. “드문 단어일수록 중요”라는 순서는 유지하면서 격차만 완만하게 줄인다
  • 직관적으로도 “DF가 10배 드물다”가 “중요도 10배”가 아니라 “한 단계 더 중요” 정도로 느끼는 것이 자연스럽다 — 로그는 ‘곱셈 차이’를 ‘덧셈 차이’로 바꾼다
  • 덤으로 DF에 1을 더하는(스무딩) 변형은 분모가 0이 되는 것을 막는다

Q5문서 길이가 서로 다를 때 코사인 유사도가 유리한 이유는?
코사인은 벡터의 크기(길이)가 아니라 방향(각도) — 즉 단어 구성 ‘비율’만 비교하기 때문에, 길게 쓴 문서와 짧게 쓴 문서도 내용이 같으면 같다고 판정한다.

유클리디언 = √((2−1)² + (2−1)²)   = 1.414   # 길이 차이 때문에 멀다고 판정
코사인 식 \frac{\mathbf{A}\cdot\mathbf{B}}{\lVert\mathbf{A}\rVert\lVert\mathbf{B}\rVert}의 분모가 각 벡터를 자기 길이로 나눠 길이를 1로 맞추는 역할을 한다. 그래서 짧은 검색어와 긴 문서, 한 줄 리뷰와 긴 리뷰를 공정하게 비교할 수 있다. 유클리디언 · 맨해튼도 쓰려면 먼저 L1/L2 정규화로 길이를 맞춰야 한다. → 5.3.2 · 5.3.3

내 메모 — “횟수가 늘어날수록 추가로 주는 정보가 줄어드니 로그를 씌워 증가폭을 완만하게 만든다.”

def sublinear_tf(dtm):
    out = np.zeros_like(dtm, dtype=float)   # 로그 결과(소수)를 담으려고 float
    mask = dtm > 0                          # dtm 과 같은 모양의 True/False 행렬
    out[mask] = 1 + np.log(dtm[mask])       # 0 에 log 를 씌우면 -inf 라 반드시 마스크로 거른다
    return out

def bm25_idf(dtm):
    N = dtm.shape[0]
    df_ = (dtm > 0).sum(axis=0)             # DF = '등장한 문서 수' (등장 횟수가 아님)
    return np.log(1 + (N - df_ + 0.5) / (df_ + 0.5))

    mat = sublinear_tf(dtm) * bm25_idf(dtm)              # 서브리니어 TF × BM25 IDF
    norms = np.linalg.norm(mat, axis=1, keepdims=True)   # 각 문서 벡터의 L2 노름
    norms[norms == 0] = 1.0                              # 단어가 하나도 없는 문서는 0 으로 나누지 않게
    return mat / norms                                   # 행마다 길이를 1 로

def max_abs_diff(dtm):
    return float(np.abs(my_bm25_tfidf(dtm) - compute_tfidf(dtm)).max())

결과 — 전체 코퍼스에서 두 방식의 최대 차이 0.1931. 같은 문서의 상위 단어도 달라진다(문서 0: Part 1은 매력적 0.767 · 각본 0.588 · 이 0.256 → BM25 변형은 매력적 0.816 · 각본 0.565 · 이 0.123). 흔한 조사의 가중치가 더 세게 깎인다. 20/20점

def pair_cosine(tokens1, tokens2):
    vb = build_vocab([tokens1, tokens2])       # 두 문장만으로 사전을 만든다
    if len(vb) == 0:
        return 0.0
    mat = compute_tfidf(build_dtm([tokens1, tokens2], vb))
    return float(cosine_similarity(mat[0], mat[1]))

def hybrid_similarity(tokens1, tokens2, w=0.5):
    if not tokens1 and not tokens2:
        return 1.0                              # 둘 다 비면 1.0
    return float(w * jaccard_similarity(tokens1, tokens2)
                 + (1 - w) * pair_cosine(tokens1, tokens2))

과제 5스무딩 계수 탐색 — 왜 alpha가 크면 나빠지나

내 메모 — “스무딩은 학습 때 한 번도 못 본 단어 때문에 확률이 0이 되는 걸 막으려고 모든 단어의 등장 횟수에 미리 더해 주는 가짜 횟수”다. 이것이 없으면 “연출도 훌륭하고 배우도 최고인데 형편없는 장면이 하나 있다” 같은 리뷰는 P(\text{형편없}\mid\text{긍정})=0 때문에 긍정 확률이 무조건 0이 된다 — 곱셈에 0이 하나라도 끼면 전체가 0이 되니까.

def choose_alphas():
    return [0.01, 0.1, 0.5, 1.0, 5.0, 10.0]     # 자릿수를 바꿔 가며 넓게

def choose_best_alpha(alphas):                  # f1 이 가장 높은 alpha
    best_alpha, best_f1 = None, -1.0
    for a in alphas:
        pred = MyMultinomialNB(alpha=a).fit(X_tr, y_tr).predict(X_te)
        f1 = classification_scores(y_te, pred)['f1']
        if f1 > best_f1:
            best_alpha, best_f1 = a, f1
    return best_alpha
