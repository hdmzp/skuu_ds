13.1

언어 분석 기술의 발전 흐름교안 3 · 4p · 왜 딥러닝인가

사람이 자질을 설계하던 시대 → 스스로 배우는 시대 (교안 4p)

규칙 기반 · 통계 기반딥러닝
자질(feature)사람이 직접 설계 — ‘앞 단어가 조사인가’, ‘-다로 끝나는가’ 같은 규칙 · 템플릿대규모 말뭉치에서 자질 표현을 스스로 학습(임베딩)
과제의 모양형태소 분석 · 품사 태깅 · 개체명 인식을 각각 다른 방법으로셋 다 시퀀스 레이블링 하나로 통합
시퀀스 레이블링 = 입력 열 x₁ … xL의 위치마다 레이블 하나를 붙여 같은 길이의 레이블 열 y₁ … yL을 내는 문제. 품사 태깅은 형태소마다 품사, 개체명 인식은 토큰마다 B-PER · I-PER · O 같은 태그를 붙인다. 12주차 입출력 구조로 말하면 many-to-many(같은 길이)다 — 감정 분류(many-to-one)와 달리 return_sequences=True로 모든 시점의 출력을 쓴다(13.16 실습 5).
13.2

형태소 분석 · 품사 태깅 개요교안 5~12p · 교착어 한국어

형태소 분석과 품사 태깅 (교안 5 · 7p)

  • 형태소 분석 — 형태소를 비롯해 어근 · 접두사 · 접미사 · 품사(POS) 등 언어적 속성의 구조를 파악하는 것. 자연언어 분석의 첫 단계로 입력 문자열을 형태소 열로 바꾼다
  • 품사 태깅 — 형태소 분석 결과를 토대로 각 형태소에 태그를 다는 작업(분석 → 태깅 순서)
\text{나는 밥을 먹는다}\;\Rightarrow\;\text{나/NP + 는/JX + 밥/NNG + 을/JKO + 먹/VA + 는/EPT + 다/EFN}

형태소 분석만 하면 ‘나 + 는 + 밥 + 을 + 먹 + 는 + 다’(7개), 품사 태깅까지 하면 위처럼 태그가 붙는다. NP 대명사 · JX 보조사 · NNG 일반 명사 · JKO 목적격 조사 · EPT 시제 선어말 어미 · EFN 평서형 종결 어미.

정정 · 주의 — ‘먹/VA’는 교안 예시 그대로다 — 세종 태그에서 VA는 형용사, 동사는 VV라 ‘먹다’는 원래 VV가 맞다. 또 EPT · EFN은 옛 21세기 세종 태그 표기이고, 아래 차트(현행 세종 태그)에서는 EP · EF로 쓴다. 시험(100문제 12번)은 교안 표기 그대로 먹/VA, 다/EFN을 고른다.

세종 품사 태그 차트 (교안 5 · 6p)

대분류태그 (설명)
체언NNG 일반 명사 · NNP 고유 명사 · NNB 의존 명사 · NR 수사 · NP 대명사
용언VV 동사 · VA 형용사 · VX 보조 용언 · VCP 긍정 지정사(이다) · VCN 부정 지정사(아니다)
관형사 · 부사 · 감탄사MM 관형사 · MAG 일반 부사 · MAJ 접속 부사 · IC 감탄사

어미EP 선어말 · EF 종결 · EC 연결 · ETN 명사형 전성 · ETM 관형형 전성
접사 · 어근XPN 체언 접두사 · XSN 명사 파생 · XSV 동사 파생 · XSA 형용사 파생 접미사 · XR 어근

대분류 함정 — NR(수사)은 ‘수’라서 용언처럼 보이지만 체언이다(100문제 9번). 대분류에 ‘숙어’는 없다(7번). 이름 첫 글자로 외우면 쉽다: N=체언, V=용언, J=조사, E=어미, X=접사 · 어근, S=부호.

왜 한국어는 어절로 자르면 안 되나 — 교착어 (교안 8 · 9 · 12p)

  • 영어는 대부분 어절 = 형태소 — ‘I like cats’는 띄어 쓴 단위가 거의 형태소이고, cats만 cat + -s로 나누면 된다
  • 한국어는 교착어 — 하나의 어근에 접사 · 조사가 여러 개 붙어 한 어절이 된다. ‘잡히셨겠더라’는 한 어절이지만 잡- + -히- + -시- + -었- + -겠- + -더라, 형태소 6개
  • ‘먹-’은 먹어 · 먹을 · 먹고로 바뀌어, 어절 단위로만 나누면 모두 다른 단어로 취급된다 — 사전이 터지고 의미가 흩어진다
  • 그래서 어근과 접사 · 조사를 분리해야 뜻을 알 수 있고, 신경망은 음절 단위 입력을 널리 쓴다(12p)
🔎 ‘잡히셨겠더라’를 한 칸씩
형태소잡--히--시--었--겠--더라
역할어간(잡다)피동 접미사주체 높임과거추측회상 종결
뜻: ‘(그분이) 잡히셨을 것 같더라’. 표면의 ‘셨’은 ‘시 + 었’이 한 음절로 합쳐진 꼴이다 — 그래서 형태소 분석은 단순히 자르기가 아니라 원형 복원까지 해야 한다(실습 1의 kkma가 ‘쪄줄래’를 ‘찌 + 어 + 주 + ㄹ래’로 복원한 것과 같은 일).

형태소 분석 방법 세 갈래 (교안 9~11p)

방법어떻게단점
규칙 기반전문가가 언어학 규칙에 따라 직접 형태소를 나누고 태깅규칙이 많고 복잡해 어렵고, 지식이 많이 필요
통계 기반두 단계 — ① 가능한 모든 형태소 후보 생성 ② 후보마다 품사 태깅해 최적 결과 선택자질을 사람이 설계(13.4)
딥러닝 기반신경망이 많은 자료에서 분석 방법을 학습대규모 학습 데이터 필요(세종 말뭉치, 13.5)
13.3

KoNLPy 형태소 분석 도구교안 13~15p

KoNLPy와 분석기 선택 기준 (교안 13 · 14p)

  • KoNLPy — 파이썬에서 여러 한국어 형태소 분석기를 모아 편리하게 쓸 수 있게 만든 패키지. 한나눔(Hannanum) · 꼬꼬마(Kkma) · 코모란(Komoran) · Mecab · Okt(옛 Twitter)를 제공한다(자바 JDK에 의존)
  • 분석기마다 품사 태그 종류와 방법이 달라 ‘Korean POS tag comparison chart’로 비교한다
  • 선택 기준 — 처리 속도 · 태그셋의 세밀도 · 사용자 사전 지원 · 신조어 · 구어체 처리 능력
from konlpy.tag import Okt, Kkma, Komoran
text = '아버지가 방에 들어가신다'
for tagger in [Okt(), Kkma(), Komoran()]:
    print(type(tagger).__name__, tagger.pos(text))
Okt     [('아버지', 'Noun'), ('가', 'Josa'), ('방', 'Noun'), ...]
Kkma    [('아버지', 'NNG'), ('가', 'JKS'), ('방', 'NNG'), ...]
Komoran [('아버지', 'NNG'), ('가', 'JKS'), ('방', 'NNG'), ...]

같은 ‘가’가 Okt에서는 Josa(영어 단어 태그), Kkma · Komoran에서는 JKS(세종 계열 주격 조사)다 — 태그 체계가 다르면 분석기를 바꿀 때 뒤 단계 코드도 바꿔야 한다(과제 서술형 1-2의 3번).

KoNLPy가 아닌 것 — Stanford CoreNLP는 영어 등 다국어 도구다(100문제 17번). 분석기 선택 기준에 ‘손실 함수 종류’ 같은 학습 세부는 없다(19번).
13.4

딥러닝 이전 — HMM · CRF와 그 한계교안 16~18p

HMM — 은닉 마르코프 모델 (교안 16p)

  • x(t) = 시간 t의 은닉 상태(품사 태깅에서는 품사), y(t) = 표면적으로 관측된 값(단어)
  • 1차 마르코프 가정 — x(t)는 바로 전 x(t−1)에서만 직접 영향을 받는다. 그 이전 상태들은 연쇄적으로 이어져 결과에 간접적으로 담긴다

CRF — 조건부 랜덤 필드 (교안 17p)

  • 배열을 입력받아 같은 길이의 결과를 돌려준다 — 시퀀스 레이블링에 딱 맞는다
  • 문장 · 단어 위치 · 레이블 정보를 받아 어떤 레이블이 얼마나 적합한지 점수를 매긴다
  • 장점: 이전 상태(이전 태그)를 확인할 수 있고, 문맥을 직접 이용해 형태소 분석에서 더 좋은 성능

딥러닝 이전 방법의 한계 (교안 18p)

한계
HMM관측 독립 가정 — 각 단어는 자기 품사에서만 생긴다고 보므로 ‘앞뒤 단어 · 접미사 · 대문자 여부’ 같은 풍부한 문맥 자질을 쓰기 어렵다 · 학습 말뭉치에 없는 미등록어(OOV)에 취약
CRF어떤 자질을 쓸지 사람이 자질 템플릿을 설계 · 자질 수가 늘면 학습 · 추론 비용 급증
공통단어를 이산 기호로 다뤄 의미적 유사성(‘강아지’와 ‘개’가 비슷)을 반영하지 못한다 → 임베딩과 신경망의 분산 표현(distributed representation)이 해결
🔎 HMM과 CRF, 한 줄로 차이 — HMM은 ‘품사가 단어를 만들어 낸다’는 생성 모델 P(x, y)이라 단어끼리는 서로 독립이라고 가정해야 계산이 된다. CRF는 문장 전체가 주어졌을 때 태그열의 확률 P(y\mid x)를 바로 모델링하는 판별 모델이라, 입력 쪽 자질을 얼마든지 겹쳐 써도 된다. 둘 다 ‘태그 → 다음 태그’ 전이를 쓰는 점은 같고, 이 전이 아이디어가 13.5의 Bi-LSTM-CRF에서 CRF 층으로 그대로 살아남는다.
생성 모델 vs 판별 모델 — 데이터가 만들어지는 과정까지 배우나, 정답 경계만 배우나
  • 판별 모델(Discriminative) — 입력 X(문장 전체)가 주어졌을 때 정답 Y(태그열)가 나올 조건부 확률 P(Y\mid X)를 직접 학습한다. 예: CRF, 로지스틱 회귀
  • 생성 모델(Generative) — 입력과 정답의 결합 확률 P(X,Y)를 먼저 학습한 뒤, 거기서 필요한 확률을 계산한다. 예: HMM, 나이브 베이즈
구분생성 모델판별 모델
핵심 목적데이터가 만들어지는 과정(분포) 자체를 학습입력이 주어졌을 때 정답을 맞히는 기준을 학습
학습하는 확률결합 확률 P(x,y) 또는 P(x\mid y)조건부 확률 P(y\mid x)
비유 (개 vs 고양이)개와 고양이의 생김새를 각각 완벽히 익혀 직접 그림을 그릴 수 있는 수준둘을 가르는 결정적인 차이(귀 모양 등)만 찾아내는 수준
품사 태깅에서 던지는 질문“이 품사(y)라면 어떤 단어(x)가 나올까?”“이 문장(x)이 주어졌을 때 가장 알맞은 품사(y)는?”
장점새 데이터를 생성할 수 있다 · 데이터가 적을 때 유리할 수 있다분류(예측) 성능이 대체로 더 좋다 · 맞히는 데 필요한 것에만 집중
대표 예HMM · 나이브 베이즈 · GAN · 확산 모델(Diffusion)CRF · 로지스틱 회귀 · SVM · 일반적인 딥러닝 분류기

식으로 보면 — 생성 모델도 결국 태그를 고를 때는 P(y\mid x)가 필요한데, 베이즈 규칙으로 돌아서 구한다. 판별 모델은 그 값을 바로 계산한다.

HMM (생성) — 품사가 단어를 만들어 내는 이야기

P(x,y)=\prod_{i}\underbrace{P(y_i\mid y_{i-1})}_{\text{전이: 다음 품사}}\;\underbrace{P(x_i\mid y_i)}_{\text{방출: 그 품사가 이 단어를 낼 확률}}\qquad\Rightarrow\qquad \hat y=\arg\max_y P(x,y)

CRF (판별) — 문장 전체를 보고 태그열에 점수를 매김

P(y\mid x)=\frac{\exp\big(\sum_i[\,\text{전이 점수}(y_{i-1},y_i)+\text{자질 점수}(y_i,x,i)\,]\big)}{Z(x)}

HMM의 방출 확률 P(x_i\mid y_i)에는 단어 하나만 들어간다(관측 독립 가정) — 그래서 ‘앞 단어가 무엇인가’, ‘-하다로 끝나는가’ 같은 단서를 넣을 자리가 없다. CRF의 자질 점수는 문장 x 전체와 위치 i를 함께 보므로 그런 단서를 얼마든지 겹쳐 쓸 수 있다. Z(x)는 가능한 모든 태그열의 점수 합으로, 전체 확률이 1이 되게 나누는 값이다.

예: “배를 먹었다”의 ‘배’ — HMM은 “명사라면 ‘배’라는 단어가 나올 확률 P(\text{배}\mid\text{명사})”처럼 단어 생성 확률을 따진다. CRF는 “뒤에 ‘먹었다’가 온다 → 먹을 수 있는 명사(과일) 쪽 점수 +”처럼 문장 속 단서를 직접 점수로 쓴다.

결론 — 품사 태깅 · 개체명 인식(NER)처럼 “주어진 문장에 정확한 태그를 붙이는 것”이 최종 목적이면, 단어가 생겨날 확률까지 모형으로 만들 필요가 없는 판별 모델(CRF)이 목적에 더 맞는다. 그래서 13.5의 Bi-LSTM-CRF도 맨 위에 CRF를 둔다.

주의 — ‘판별 모델이 계산이 효율적’은 맞히는 데 필요 없는 것(단어 분포)을 모델링하지 않는다는 뜻이다. 학습 자체는 오히려 CRF가 더 무겁다: HMM은 말뭉치에서 ‘명사 다음 동사가 몇 번’, ‘명사가 ‘배’인 경우가 몇 번’을 세기만 하면 되지만, CRF는 Z(x)를 계산하며 경사 하강으로 가중치를 반복 학습해야 한다. 같은 생성 · 판별 구분이 다른 과목에도 나온다 — 컴퓨터비전 11주차(Naive Bayes vs KNN · SVM) · 기계학습특론 12주차 CRF · 기계학습특론 13주차 GAN(생성 모델).

Bi-LSTM-CRF — 임베딩 → Bi-LSTM → CRF (교안 25p)

  • Bi-LSTM이 각 위치에서 왼쪽 문맥(→)과 오른쪽 문맥(←)을 이어 붙인 표현 h를 만든다(12주차 양방향)
  • CRF가 그 h를 보고 문장 전체의 최적 태그열을 한꺼번에 결정한다

어떻게위치마다 가장 큰 점수만 고른다전이 행렬 A를 학습해 ‘O → I-X 금지’ 같은 태그열 제약을 반영

점수 함수 · 학습 · Viterbi 디코딩 (교안 27p)

s(x,y)=\sum_{i}A(y_{i-1},\,y_i)+\sum_{i}P(i,\,y_i)\qquad(\text{전이 점수}+\text{방출 점수})

P(i, y) = Bi-LSTM이 위치 i에서 태그 y에 준 점수(방출), A(y′, y) = 태그 y′ 다음에 y가 오는 점수(전이). 학습은 정답 경로 점수는 높이고 모든 경로 점수의 합(log-sum-exp)은 낮춘다 — 즉 정답 경로의 확률 e^{s(x,y^*)}/\sum_y e^{s(x,y)}을 키운다. 추론은 Viterbi로 최대 점수 경로를 O(L\cdot T^2)에 찾는다(L 길이, T 태그 수).

🔎 숫자로 — softmax는 틀리고 Viterbi는 맞히는 예 (직접 계산)

태그 3개(B-PER · I-PER · O), 문장 ‘이 순 신’. Bi-LSTM 방출 점수 P와 전이 점수 A가 이렇다고 하자.

방출 P이순신
B-PER1.00.10.1
I-PER0.21.51.4
O1.20.30.5

전이 A: 시작 → I-PER = −∞, O → I-PER = −∞(금지), B-PER → I-PER = +0.5, I-PER → I-PER = +0.5, 나머지 0.

  • softmax(위치별 최댓값): 이 = O(1.2), 순 = I-PER, 신 = I-PER → O I-PER I-PER — 불가능한 태그열
  • Viterbi: δ = 그 위치에서 그 태그로 끝나는 최고 점수.
    • 이: δ(B) = 1.0 · δ(I) = −∞ · δ(O) = 1.2
    • 순: δ(I) = max(1.0 + 0.5, −∞, 1.2 − ∞) + 1.5 = 3.0(B에서 옴) · δ(B) = 1.2 + 0.1 = 1.3 · δ(O) = 1.2 + 0.3 = 1.5
    • 신: δ(I) = max(1.3 + 0.5, 3.0 + 0.5, −∞) + 1.4 = 4.9(I에서 옴) · δ(B) = 3.0 + 0.1 = 3.1 · δ(O) = 3.0 + 0.5 = 3.5
  • 최고 4.9를 거꾸로 따라가면 I ← I ← B → B-PER I-PER I-PER. 확인: 1.0 + 0.5 + 1.5 + 0.5 + 1.4 = 4.9 ✓, O O O는 2.0, O B I는 3.2

왜 O(L·T²)인가 — 위치마다 ‘현재 태그 T개 × 이전 태그 T개’만 비교하면 되기 때문이다. CoNLL-2003처럼 태그 9개 · 길이 80이면 80 × 81 = 6,480번, 모든 경로를 다 세면 9⁸⁰개다. 각 위치에서 ‘지금까지의 최선’만 들고 가는 동적 계획법이라 가능하다.

Bi-LSTM-CRF에서 갈리는 곳 — 순서는 임베딩 → Bi-LSTM → CRF(39번). CRF는 전이 행렬로 태그열 제약을 넣는 층이지 문맥을 읽는 층이 아니다(문맥은 Bi-LSTM). 학습은 log-sum-exp ‘낮추기’, 추론은 Viterbi ‘최대’ 경로 — 방향을 바꾼 보기에 주의(42번).

한국어 의미역 분석교안 28~33p (교안 13.6 소개 포함)

의미역 분석이란, 그리고 왜 심층학습인가 (교안 29 · 30p)

의미역 분석(Semantic Role Labeling, SRL) = 문장에서 술어(동사 등)를 찾고, 그 술어에 딸린 논항들이 ‘누가(행위자) · 무엇을(대상) · 어디서 · 언제’ 같은 어떤 역할을 하는지 붙이는 일. 예: “철수가 도서관에서 책을 읽었다” → 술어 읽다, 철수 = ARG0(행위자), 책 = ARG1(대상), 도서관에서 = ARGM-LOC(장소). 이것도 단어마다 B-ARG0 · I-ARG1 같은 태그를 다는 시퀀스 레이블링이다.
  • 기존 기계학습은 사람이 추출한 특징을 받는다 — 모듈마다 적합한 특징을 뽑고 최적 조합을 찾는 데 시간이 많이 든다 → 특징을 높은 수준으로 추상화하는 심층학습
  • LSTM은 순차 데이터에 적합하지만, 높은 성능의 의미역 분석에 가장 많이 쓰는 특징은 구문 분석 정보 — 술어와 논항 사이의 의존 관계가 담겨 있기 때문

  • BERT-kNN — BERT 문맥 벡터에 kNN을 적용한, 사전학습 모델을 이용한 대표적 초기 접근. 이후 gloss 정보를 함께 쓰는 BEM · ESCHER · ConSeC가 더 높은 성능을 보고했다
  • 처리: 의미 레이블이 붙은 학습 문장을 BERT에 넣되, 레이블 붙은 단어는 원래 단어로 되돌려 입력 → 그 단어의 출력 벡터를 의미 벡터로 치환해 저장 → 새 문장의 중의어 벡터와 kNN으로 가장 가까운 의미를 고른다
🔎 BERT-kNN을 숫자로 — 학습 문장에서 ‘배’의 BERT 벡터를 의미별로 모아 두었다고 하자(2차원으로 단순화). 배_01(과일) 예문 벡터 [0.9, 0.1] · [0.8, 0.2], 배_02(선박) [0.1, 0.9] · [0.2, 0.8]. 새 문장 “항구에 배가 들어왔다”의 ‘배’ 벡터가 [0.15, 0.85]라면, 코사인 유사도가 선박 쪽 두 벡터와 0.99 이상, 과일 쪽과는 0.28 · 0.41이라 k = 3의 이웃 중 2개가 배_02 → 선박. 같은 글자 ‘배’라도 BERT는 문맥에 따라 다른 벡터를 내므로(word2vec은 단어마다 벡터 하나) 이 방식이 통한다. 계산: [0.15, 0.85] · [0.1, 0.9] = 0.78, 길이 0.863 · 0.906 → 0.998 / [0.9, 0.1]과는 0.22 / (0.863 × 0.906) ≈ 0.28.

방법 ② 지식 상호 보완 모델 — Luo et al. (교안 37~39p)

Context 모듈중의어가 있는 문장을 GloVe 입력 → Bi-LSTM 정방향 · 역방향 벡터를 concatenate
Gloss 모듈중의어의 사전 정의(gloss)를 같은 방식(GloVe + Bi-LSTM)으로 표현
Memory 모듈Context 벡터와 Gloss 벡터 사이 Attention을 계산하고, 이전 메모리로 현재 메모리를 반복 갱신
Scoring 모듈Context 벡터 + 마지막 Attention 결과로 중의어의 의미를 선택

레이블된 데이터(문맥)와 사전 지식(gloss)이라는 두 정보원을 서로 보완하게 묶은 모델이다 — 레이블 데이터가 적은 의미도 사전 정의로 버틸 수 있다.

개체명 인식(NER) · BIO 태깅 · 평가교안 41~45p

신경망 NER의 흐름 (교안 41 · 42p)

  • 개체명 인식(Named Entity Recognition) = 문장에서 사람 · 장소 · 기관 · 날짜 같은 고유한 이름을 찾아 유형을 붙이는 일
  • 처음에는 사전 · 어휘로 구성한 벡터 → Word2vec 이후 수동 자질 벡터가 단어 임베딩으로 대체
  • 한국어 · 중국어처럼 띄어쓰기만으로 단어 경계를 확정하기 어려운 언어에서는 사전 훈련된 임베딩의 영향이 특히 크다
  • 구조는 세 갈래 — 단어 단위 · 문자 단위 · 단어 + 문자 단위(13.10)

BIO와 BIOES (교안 43p)

어절이순신은1592년한산도에서일본수군을격파했다
BIOB-PEROB-DATB-LOCOB-ORGI-ORGOO
BIOESS-PEROS-DATS-LOCOB-ORGE-ORGOO
  • BIO — B(개체 시작) · I(개체 내부) · O(개체 아님)
  • BIOES — E(개체 끝) · S(단일 토큰 개체)를 더해 경계 정보를 명확히. 한 토큰짜리 ‘이순신’은 S-PER, 두 토큰 ‘일본 수군’은 B-ORG E-ORG
  • 한국어는 조사가 붙어 어절 경계와 개체 경계가 다르다(‘한산도에서’) → 형태소 · 음절 단위 태깅이 유리

학습 데이터 준비 (교안 44p)

개체명 유형 체계(PER · LOC · ORG · DAT …)가 말뭉치마다 다르고, 태깅 단위(어절 / 형태소 / 음절)를 학습 · 평가에서 일관되게 맞춰야 한다 — 어절로 학습하고 음절로 평가하면 경계가 맞을 수 없다.

평가 — 토큰 정확도가 아니라 개체 단위 F1 (교안 45p)

  • 토큰 단위 정확도는 O 태그 비중이 커 성능이 과대평가된다
  • 개체 단위 F1 — 경계와 유형이 모두 일치한 개체만 정답. seqeval 라이브러리로 계산
🔎 숫자로 — 토큰 정확도 78%인데 개체 F1은 57%

위 문장(9토큰)의 정답 개체 4개: 이순신(PER) · 1592년(DAT) · 한산도(LOC) · 일본 수군(ORG). 모델이 이렇게 예측했다: 이순신 B-PER ✓ · 1592년 B-DAT ✓ · 한산도 O(놓침) · 일본 B-ORG · 수군 O(경계 틀림) · 나머지 O.

신경망 NER 구조 — 단어 · 문자 · 단어 + 문자교안 46~49p (교안 13.10 ~ 13.12)

단어 단위 구조 (교안 46p)

문장을 단어 임베딩으로 바꿔 RNN에 넣되 정방향과 역방향으로 한 번씩 넣는다 — 단방향 정보만 쓰는 모델보다 양방향 정보를 쓴 모델의 성능이 더 좋았기 때문이다. 교안 그림: ‘New York is a long way’ → B-LOC I-LOC O O O O(Word Embedding → Word LSTM-F · Word LSTM-B → Word Representation → Label).

문자 단위 구조 (교안 47p)

문장을 문자의 연속으로 보고 RNN으로 문자마다 레이블을 예측한 뒤, 후처리로 문자 레이블을 단어 레이블로 변환한다. 문자 단위 표현으로 영어 Penn Treebank(PTB) 품사 태깅 97.8%(Ling et al., 2015 당시 최고). 문자를 보므로 처음 보는 단어(OOV)도 철자로 추측할 수 있다.

단어 + 문자 단위 구조 (교안 48 · 49p)

도메인별 지식이나 리소스를 따로 정의할 필요가 없는 강력한 NER 시스템으로 자리 잡았다. 기본 모델 둘:

문자 표현을 만드는 법그다음
첫 번째단어의 문자들을 컨볼루션으로 하나의 벡터로 → 단어 임베딩과 합침Bi-LSTM → softmax 또는 CRF
두 번째단어의 문자들을 LSTM으로 → 단어 임베딩과 연결문장 수준 Bi-LSTM → softmax 또는 CRF (Lample et al., 2016)
🔎 단어 + 문자를 함께 쓰는 이유 — 단어 임베딩은 ‘Washington’이 도시 · 사람 이름 근처라는 의미를 알고, 문자 표현은 ‘대문자로 시작 · -burg로 끝남 · -어 · -에서 같은 조사’ 같은 모양을 안다. 학습 때 못 본 이름 ‘Blackburn’은 단어 임베딩이 <UNK>지만 문자 쪽이 ‘대문자 + 이름 같은 철자’로 사람일 가능성을 잡아 준다 — 13.4의 OOV 한계에 대한 답이다. 한국어 음절 단위 입력(13.2)도 같은 이유다.

실습 2 · Lesk 알고리즘으로 중의성 해소 (교안 53p)

def compute_overlap(signature, context, stopwords):
    gloss = signature.difference(stopwords)      # 사전 정의 단어 − 불용어
    return len(gloss.intersection(context))      # 문맥과 겹치는 단어 수
sentence = "They eat a meal"
Word : eat
Sense : eat.v.02   Definition : eat a meal; take a meal
2
Best sense: Synset('eat.v.02')

Lesk = 단어의 의미 후보마다 WordNet 사전 정의(gloss) + 예문의 단어 집합(signature)을 만들고, 문맥과 가장 많이 겹치는 의미를 고른다. ‘eat a meal; take a meal’의 meal · eat이 문장과 겹쳐 겹침 2 → eat.v.02. 13.8의 ‘gloss와 문맥의 유사도’를 단어 겹침 개수로 계산한 가장 단순한 판이다.

요약 정리 (교안 72p)

  • 형태소 분석 · 품사 태깅 — 개요와 KoNLPy, 딥러닝 이전(HMM · CRF)과 딥러닝 기반(FFNN · seq2seq · CNN · Bi-LSTM-CRF)
  • Bi-LSTM-CRF — Bi-LSTM이 양방향 문맥 표현을 만들고, CRF가 태그 간 전이 제약을 반영해 최적 태그열을 Viterbi로 결정
  • 단어 의미 분석 — 한국어 의미역 분석, 심층학습 기반 중의성 해소(BERT-kNN · 지식 상호 보완 모델)
  • 개체명 인식 — 단어 · 문자 · 단어 + 문자 구조, BIO / BIOES, 개체 단위 F1
  • 최근에는 KoBERT · KoELECTRA 등 사전학습 언어모델의 토큰 분류 미세조정이 표준적 접근(규칙 기반이 표준이라는 보기는 오답 — 100번)
